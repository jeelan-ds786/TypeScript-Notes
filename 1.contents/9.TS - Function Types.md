

# Function Types in TypeScript

### Explicit Parameter Types

```ts
const funky = (
  a: number,
  b: string
) => {
  console.log(typeof a, typeof b);
};
```

✅ Preferred

**Note:** Use `string`, not `String`.

```ts
b: String ❌
b: string ✅
```

### Quick Revision

- Always type function parameters.
    
- Prefer primitive types (`string`, `number`, `boolean`).
    

# Function Parameter Type Inference

### Example

```ts
const funky = (a = 34, b = "fareed") => {
  console.log(a, b);
};
```

TypeScript infers:

```ts
a: number
b: string
```

### Valid

```ts
funky();
funky(100, "john");
```

### Invalid

```ts
funky("abc", 100);
```

❌ Error

### Interview Takeaway

> TypeScript can infer parameter types from default values.

### Quick Revision

- Default value → Type inference.
    

# Return Type Inference

### Example

```ts
const add = (a: number, b: number) => {
  return a + b;
};
```

TypeScript infers:

```ts
(a: number, b: number) => number
```

Return type automatically becomes:

```ts
number
```

### Quick Revision

- TS can infer most return types automatically.
    

# Explicit Return Types

### Example

```ts
const add = (
  a: number,
  b: number
): number => {
  return a + b;
};
```

Syntax:

```ts
(parameter types): returnType
```

### Quick Revision

- Return type comes after parameter list.
    

# Can We Omit Return Types?

### Yes

```ts
const add = (a: number, b: number) => {
  return a + b;
};
```

TS infers:

```ts
number
```

### Most Common in Frontend Projects

```ts
const add = (a: number, b: number) => {
  return a + b;
};
```

### Interview Takeaway

> TypeScript usually infers return types correctly.

### Quick Revision

- Omit when obvious.
    
- Explicit when API/public function is important.
    

# When Should We Explicitly Add Return Types?

### Public APIs

```ts
function getUser(): User {
  return user;
}
```

### Library Code

```ts
function createToken(): string {
  return token;
}
```

### React Hooks

```ts
function useAuth(): AuthState {
  return state;
}
```

### Benefits

- Better documentation.
    
- Prevent accidental return changes.
    

### Quick Revision

- Public functions → explicit return types.
    
- Internal helpers → inference is fine.
    

# Function Type Annotation

You can type the entire function.

### Example

```ts
const add:
  (a: number, b: number) => number =
  (a, b) => {
    return a + b;
  };
```

Meaning:

```txt
Accept number, number
Return number
```

### Quick Revision

- Function itself can have a type.
    

# Callback Function Types

Very common in interviews.

### Example

```ts
function process(
  callback: (value: number) => void
) {
  callback(100);
}
```

Usage:

```ts
process((value) => {
  console.log(value);
});
```

TypeScript infers:

```ts
value: number
```

### Quick Revision

- Callback types are defined like normal functions.
    

# Callback with Return Type

### Example

```ts
function calculate(
  callback: (a: number, b: number) => number
) {
  return callback(10, 20);
}
```

Usage:

```ts
calculate((a, b) => {
  return a + b;
});
```

### Callback Type

```ts
(a: number, b: number) => number
```

Meaning:

```txt
Receives:
  number, number

Returns:
  number
```

### Quick Revision

- Callback signature = parameter types + return type.
    

# Built-in Callback Example (`map`)

### Example

```ts
const numbers = [1, 2, 3];

const doubled =
  numbers.map((num) => num * 2);
```

TypeScript infers:

```ts
num: number
```

Result:

```ts
number[]
```

### Behind the Scenes

Simplified type:

```ts
map(
  callback:
    (value: number) => number
)
```

### Quick Revision

- Array methods provide callback types automatically.
    

# Callback Returning Boolean (`filter`)

### Example

```ts
const users = [1, 2, 3, 4];

const result =
  users.filter((num) => {
    return num > 2;
  });
```

Callback type:

```ts
(num: number) => boolean
```

### Quick Revision

- `filter()` callbacks return boolean.
    

# Custom Callback Type Alias

Very common in large projects.

### Example

```ts
type AddFn =
  (a: number, b: number) => number;
```

Usage:

```ts
const add: AddFn =
  (a, b) => a + b;
```

### Callback Example

```ts
type Callback =
  (value: string) => void;
```

```ts
function execute(
  cb: Callback
) {
  cb("hello");
}
```

### Quick Revision

- Complex callback types → Type Alias.
    

# Interview Gotchas

|Question|Answer|
|---|---|
|`String` or `string`?|`string`|
|Can TS infer return types?|Yes|
|Can TS infer parameter types?|Sometimes (default values, callbacks)|
|Should parameter types be omitted?|Usually no|
|Should return types be omitted?|Usually yes for simple functions|
|Callback syntax?|`(arg: Type) => ReturnType`|
|`void` means?|Function returns nothing|
|`map()` callback returns?|New value|
|`filter()` callback returns?|Boolean|

# Common Function Patterns

### Function Returning Nothing

```ts
const log =
  (msg: string): void => {
    console.log(msg);
  };
```

### Function Returning Number

```ts
const add =
  (a: number, b: number): number => {
    return a + b;
  };
```

### Callback Type

```ts
(value: string) => void
```

### Callback with Return

```ts
(a: number, b: number) => number
```

### Quick Revision

- Parameters → before `=>`
    
- Return type → after `=>`
    
- `void` → no return value
    

| Topic                   | Quick Recall                                            |
| ----------------------- | ------------------------------------------------------- |
| Parameter Types         | `(a: number, b: string)`                                |
| Preferred String Type   | `string`                                                |
| Default Value Inference | `a = 10` → number                                       |
| Return Type Inference   | Automatic                                               |
| Explicit Return Type    | `(): number => {}`                                      |
| Omit Return Type?       | Usually yes                                             |
| Public APIs             | Explicit return types preferred                         |
| Callback Type           | `(value: number) => void`                               |
| Callback Return Type    | `(a,b) => number`                                       |
| Function Alias          | `type AddFn = (a,b)=>number`                            |
| `void`                  | No return value                                         |
| Interview Rule          | Type parameters explicitly, let TS infer simple returns |
