
# Intersection Types (`&`)

- Intersection combines multiple types into one
    
- The resulting type must satisfy **all** combined types
    
- Created using `&`
    
- Quick revision: **Intersection = AND operation**
    

```ts
type Person = {
  name: string;
};

type Employee = {
  salary: number;
};

type EmployeePerson = Person & Employee;
```

Result:

```ts
{
  name: string;
  salary: number;
}
```

# How to Implement an Intersection Type

```ts
type Person = {
  name: string;
};

type Employee = {
  salary: number;
};

type EmployeePerson = Person & Employee;

const emp: EmployeePerson = {
  name: "Fareed",
  salary: 50000
};
```

### Interview Recall

- Must provide properties from **both** types
    
- Missing even one property → Error
    

# Can a Class Implement an Intersection Type?

✅ Yes

```ts
type Person = {
  name: string;
};

type Employee = {
  salary: number;
};

type EmployeePerson = Person & Employee;

class Developer implements EmployeePerson {
  name = "Fareed";
  salary = 50000;
}
```

TypeScript checks that the class satisfies **all properties** from both types.

### Interview One-Liner

> A class can implement an intersection type if the intersection resolves to an object shape.

# How Do We Achieve Intersection Using Interfaces?

Interfaces don't use `&`.

Instead, use `extends`.

```ts
interface Person {
  name: string;
}

interface Employee {
  salary: number;
}

interface EmployeePerson
  extends Person, Employee {}
```

Equivalent to:

```ts
type EmployeePerson =
  Person & Employee;
```

### Interview Recall

```txt
Type      → &
Interface → extends
```

Both produce:

```ts
{
  name: string;
  salary: number;
}
```

# Multiple Interface Extension

```ts
interface Flyable {
  fly(): void;
}

interface Swimmable {
  swim(): void;
}

interface Duck
  extends Flyable, Swimmable {
  name: string;
}
```

Duck contains:

```txt
fly()
swim()
name
```

This is effectively an intersection of interfaces.

# Interface vs Intersection

### Using Type

```ts
type A = {
  a: string;
};

type B = {
  b: string;
};

type C = A & B;
```

### Using Interface

```ts
interface A {
  a: string;
}

interface B {
  b: string;
}

interface C extends A, B {}
```

Both result in:

```ts
{
  a: string;
  b: string;
}
```

# Common Interview Questions

|Question|Answer|
|---|---|
|What is an intersection type?|Combines multiple types into one|
|Which operator creates an intersection?|`&`|
|Does intersection mean OR?|No, it means AND|
|Can a class implement an intersection type?|Yes|
|How do interfaces create intersections?|Using `extends`|
|Can an interface extend multiple interfaces?|Yes|

# Interview Traps

|Trap Question|Correct Answer|
|---|---|
|Is `A & B` either A or B?|No, it is both A and B|
|Does intersection remove properties?|No, it combines them|
|Can interface use `&` directly?|No|
|Can class implement multiple interfaces?|Yes|
|Is `extends A, B` similar to `A & B`?|Yes|

# Quick Recall

- Intersection = AND (`&`)
    
- Object must satisfy all types
    
- Class can implement intersection types
    
- Interface equivalent = `extends`
    
- Multiple interface inheritance acts like intersection
