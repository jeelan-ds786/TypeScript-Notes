# Interfaces vs Types

## Why Use `interface` Instead of `type` for Objects?

Both can shape objects:

```ts
interface User {
  name: string;
  age: number;
}
```

```ts
type User = {
  name: string;
  age: number;
};
```

Both work.

### Industry Preference

- `interface` is preferred for object contracts
    
- Better support for extension and declaration merging
    
- Common in React, Angular, enterprise projects
    
- Easier for large teams to extend
    

### Interview One-Liner

> Use `interface` for object shapes and contracts. Use `type` for unions, intersections, mapped types, and advanced type transformations.

# Interface Declaration Merging

This is the biggest interview point.

```ts
interface User {
  name: string;
}
```

Later:

```ts
interface User {
  age: number;
}
```

TypeScript automatically merges them:

```ts
interface User {
  name: string;
  age: number;
}
```

Valid:

```ts
const user: User = {
  name: "Fareed",
  age: 21
};
```

### Why Useful?

Large libraries can extend existing interfaces without modifying original code.

Example:

```ts
interface Window {
  myAppVersion: string;
}
```

Browser's existing `Window` interface gets extended.

### Interview Trap

|Question|Answer|
|---|---|
|Can interfaces merge automatically?|Yes|
|Can type aliases merge automatically?|No|

# Why Doesn't `type` Merge?

```ts
type User = {
  name: string;
};
```

Again:

```ts
type User = {
  age: number;
};
```

❌ Error

```txt
Duplicate identifier 'User'
```

Type aliases are exact definitions.

No merging support.

### Interview Recall

- Interface = open for extension
    
- Type = closed definition
    

# Extending Interfaces

Parent:

```ts
interface Person {
  name: string;
}
```

Child:

```ts
interface Employee extends Person {
  salary: number;
}
```

Usage:

```ts
const emp: Employee = {
  name: "Fareed",
  salary: 50000
};
```

### What Happened?

```txt
Person
  ↑
Employee
```

Employee inherits all properties from Person.

### Quick Recall

- `extends` = interface inheritance
    

# Multiple Interface Inheritance

```ts
interface Flyable {
  fly(): void;
}

interface Swimmable {
  swim(): void;
}

interface Duck
  extends Flyable, Swimmable {
  name: string;
}
```

Duck gets:

```txt
fly()
swim()
name
```

### Interview Recall

Interfaces support multiple inheritance.

# Type Intersection Equivalent

With types:

```ts
type Flyable = {
  fly(): void;
};

type Swimmable = {
  swim(): void;
};

type Duck =
  Flyable &
  Swimmable & {
    name: string;
  };
```

This is how types combine.

### Difference

|Feature|Interface|Type|
|---|---|---|
|extends|✅|❌|
|Declaration merging|✅|❌|
|Intersection (`&`)|❌|✅|
|Union (`|`)|❌|

### Interview One-Liner

> Interfaces extend, Types intersect.

# If Interfaces Don't Exist in JavaScript, How Do They Compile?

Excellent interview question.

TypeScript removes interfaces completely.

Input:

```ts
interface User {
  name: string;
}

const user: User = {
  name: "Fareed"
};
```

Generated JavaScript:

```js
const user = {
  name: "Fareed"
};
```

Notice:

```txt
Interface disappeared.
```

### Why?

Interfaces are compile-time only.

They exist only for type checking.

No JavaScript code is generated.

### Interview Recall

- Interface = TypeScript-only construct
    
- Removed during compilation
    

# What About Abstract Classes?

Input:

```ts
abstract class Animal {
  abstract speak(): void;
}
```

Generated JavaScript:

```js
class Animal {}
```

TypeScript removes:

- `abstract`
    
- type annotations
    

Only JavaScript-compatible code remains.

### Important

TypeScript compiler checks rules first:

```ts
const a = new Animal();
```

❌ Compile Error

Since code fails type checking, it should not reach production.

### Interview Recall

- Abstract class rules are enforced before compilation
    
- JavaScript receives normal class code
    

# TypeScript Compilation Process

```txt
TypeScript Code
      ↓
Type Checking
      ↓
Remove TS Features
      ↓
Generate JavaScript
      ↓
Browser / Node.js
```

Things removed:

```txt
Interfaces
Types
Abstract keyword
Access modifiers
Readonly
Type annotations
Generics
```

Example:

```ts
class User {
  private name: string;

  constructor(name: string) {
    this.name = name;
  }
}
```

Generated JS:

```js
class User {
  constructor(name) {
    this.name = name;
  }
}
```

No trace of:

- private
    
- string
    

They were TypeScript-only checks.

# Quick Recall

- Interface = object contract
    
- Type = general type alias
    
- Interface supports declaration merging
    
- Interface supports `extends`
    
- Type uses `&` intersections
    
- Interfaces disappear after compilation
    
- Types disappear after compilation
    
- Abstract is checked by TS and removed
    
- Browser only sees JavaScript
