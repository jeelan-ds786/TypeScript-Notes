
# TypeScript Classes

- Blueprint for creating objects
    
- Supports OOP concepts like encapsulation, inheritance, polymorphism
    
- Adds type safety on top of JavaScript classes
    
- Compiles to normal JavaScript classes
    
- Quick revision: **Class = template, Object = instance**
    

# Class Syntax

```ts
class User {
  name: string;

  constructor(name: string) {
    this.name = name;
  }

  greet() {
    return `Hello ${this.name}`;
  }
}
```

- `constructor()` initializes object
    
- Methods are shared across instances
    
- `new` creates an object
    
- Quick revision: **constructor runs during object creation**
    

# Access Modifiers

### `public`

```ts
class User {
  public name: string;
}
```

- Accessible everywhere
    
- Default modifier in TypeScript
    

### `private`

```ts
class User {
  private password: string;
}
```

- Accessible only inside class
    

### `protected`

```ts
class User {
  protected age: number;
}
```

- Accessible inside class and subclasses
    

### Interview Trap

|Question|Answer|
|---|---|
|Default access modifier?|`public`|
|Can child class access private member?|No|
|Can child class access protected member?|Yes|

### Quick Recall

- public → everywhere
    
- private → class only
    
- protected → class + child classes
    

# Parameter Properties

```ts
class User {
  constructor(public name: string) {}
}
```

Equivalent to:

```ts
class User {
  public name: string;

  constructor(name: string) {
    this.name = name;
  }
}
```

- Reduces boilerplate
    
- Frequently asked in interviews
    
- Quick revision: **declare + assign in one line**
    

# Readonly Properties

```ts
class User {
  constructor(readonly id: number) {}
}
```

```ts
user.id = 10; // Error
```

- Value can be assigned only once
    
- Useful for IDs and immutable fields
    

### Interview Trap

|Question|Answer|
|---|---|
|Same as const?|No|
|Can readonly be initialized in constructor?|Yes|

### Quick Recall

- readonly = write once
    

# Getters and Setters

```ts
class User {
  private _name = "";

  get name() {
    return this._name;
  }

  set name(value: string) {
    this._name = value;
  }
}
```

- Control access to properties
    
- Add validation logic
    
- Hide internal implementation
    

### Interview Question

**Why use getters/setters?**

**Answer:** To encapsulate validation and control access to data.

# Static Members

```ts
class MathUtil {
  static PI = 3.14;
}
```

Usage:

```ts
MathUtil.PI;
```

- Belongs to class, not object
    
- No need to create instance
    

### Interview Trap

|Question|Answer|
|---|---|
|Access static via object?|No|
|Access static via class?|Yes|

### Quick Recall

- static = class-level member
    

# Inheritance

```ts
class Animal {
  eat() {
    console.log("Eating");
  }
}

class Dog extends Animal {
  bark() {
    console.log("Barking");
  }
}
```

- Child inherits parent members
    
- Promotes code reuse
    

### Quick Recall

- `extends` = inheritance
    

# Method Overriding

```ts
class Animal {
  speak() {
    console.log("Animal sound");
  }
}

class Dog extends Animal {
  speak() {
    console.log("Bark");
  }
}
```

- Child provides its own implementation
    
- Runtime polymorphism
    

### Interview Question

**What is method overriding?**

**Answer:** Child class replaces parent method implementation with its own version.

# Abstract Classes

```ts
abstract class Animal {
  abstract speak(): void;
}
```

```ts
class Dog extends Animal {
  speak() {
    console.log("Bark");
  }
}
```

- Cannot create object of abstract class
    
- Used as a blueprint for subclasses
    

### Interview Trap

|Question|Answer|
|---|---|
|Can abstract class have methods?|Yes|
|Can abstract class be instantiated?|No|

### Quick Recall

- Abstract class = partial implementation + contract
    

# Interfaces vs Classes

```ts
interface User {
  name: string;
}
```

```ts
class Admin implements User {
  name = "Fareed";
}
```

- Interface defines contract
    
- Class provides implementation
    

### Interview Trap

|Question|Answer|
|---|---|
|Can interface have implementation?|No|
|Can class implement multiple interfaces?|Yes|

### Quick Recall

- Interface = What
    
- Class = How
    

# Implements Keyword

```ts
interface Flyable {
  fly(): void;
}

class Bird implements Flyable {
  fly() {
    console.log("Flying");
  }
}
```

- Forces class to follow interface contract
    
- Compile-time validation
    

### Quick Recall

- implements = obey interface rules
    

# Super Keyword

```ts
class Animal {
  constructor(public name: string) {}
}

class Dog extends Animal {
  constructor(name: string) {
    super(name);
  }
}
```

- Calls parent constructor
    
- Required before using `this`
    

### Interview Trap

|Question|Answer|
|---|---|
|Must `super()` be called first?|Yes|
|Used only in child classes?|Yes|

### Quick Recall

- super = parent class access
