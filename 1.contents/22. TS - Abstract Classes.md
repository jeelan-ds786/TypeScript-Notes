
# Abstract Classes in TypeScript

- `abstract` classes are **not a TypeScript-only feature**
    
- They exist in languages like:
    
    - Java
        
    - C#
        
    - Kotlin
        
    - PHP
        
- JavaScript does **not** have native abstract classes
    
- TypeScript adds compile-time support for them
    
- Quick revision: **Abstract class = blueprint that cannot be instantiated**
    

# What Makes an Abstract Class Special?

Normal class:

```ts
class Animal {
  speak() {
    console.log("Sound");
  }
}

const a = new Animal(); // ✅
```

Abstract class:

```ts
abstract class Animal {
  abstract speak(): void;
}
```

```ts
const a = new Animal();
```

❌ Error

You cannot create objects of abstract classes.

### Interview Recall

- Abstract class = incomplete class
    
- Must be extended by another class
    

# Abstract Methods

```ts
abstract class Animal {
  abstract speak(): void;
}
```

Child class:

```ts
class Dog extends Animal {
  speak() {
    console.log("Bark");
  }
}
```

If `Dog` doesn't implement `speak()`:

```ts
class Dog extends Animal {}
```

❌ Compile error

### Quick Recall

- Abstract method = contract
    
- Child class must implement it
    

# Why Not Just Use Interfaces?

Interviewers love this question.

Interface:

```ts
interface Animal {
  speak(): void;
}
```

Abstract class:

```ts
abstract class Animal {
  name = "";

  abstract speak(): void;
}
```

### Difference

|Feature|Interface|Abstract Class|
|---|---|---|
|Properties|✅|✅|
|Method Implementation|❌|✅|
|Constructor|❌|✅|
|State Storage|❌|✅|
|Contract Enforcement|✅|✅|

### Interview One-Liner

> Use an interface when you only need a contract. Use an abstract class when you want a contract plus shared implementation.

# Industrial Perspective

This is where abstract classes become valuable.

## Example 1: Payment Systems

Without abstraction:

```ts
class CreditCardPayment {
  processPayment() {}
}

class UpiPayment {
  processPayment() {}
}

class PaypalPayment {
  processPayment() {}
}
```

Repeated structure everywhere.

---

With abstract class:

```ts
abstract class Payment {
  abstract processPayment(): void;

  logTransaction() {
    console.log("Transaction logged");
  }
}
```

Implementations:

```ts
class UpiPayment extends Payment {
  processPayment() {
    console.log("UPI Payment");
  }
}
```

Every payment type:

- Must implement payment logic
    
- Reuses transaction logging
    

### Industry Benefit

- Consistent architecture
    
- Shared business logic
    
- Prevents developers from forgetting required methods
    

# Example 2: Angular Components

Very common in enterprise Angular projects.

```ts
abstract class BaseComponent {
  loading = false;

  showLoader() {
    this.loading = true;
  }

  hideLoader() {
    this.loading = false;
  }
}
```

Child components:

```ts
class UserComponent extends BaseComponent {}

class ProductComponent extends BaseComponent {}
```

Benefits:

- Shared loader logic
    
- Shared error handling
    
- Shared API utilities
    

Used heavily in large applications.

# Example 3: Logging Framework

```ts
abstract class Logger {
  abstract write(message: string): void;

  format(message: string) {
    return `[LOG] ${message}`;
  }
}
```

Implementations:

```ts
class FileLogger extends Logger {
  write(message: string) {
    console.log("Writing to file");
  }
}

class DBLogger extends Logger {
  write(message: string) {
    console.log("Writing to database");
  }
}
```

Industry usage:

- Logging systems
    
- Notification systems
    
- Payment gateways
    
- Storage providers
    

# Why Companies Use Abstract Classes

### Enforce Rules

```ts
abstract class Payment {
  abstract processPayment(): void;
}
```

Every developer must implement:

```ts
processPayment()
```

No exceptions.

---

### Share Common Logic

```ts
logTransaction()
```

Write once, reuse everywhere.

---

### Better Maintainability

If business logic changes:

```ts
abstract class Payment {
  logTransaction() {
    // changed once
  }
}
```

All child classes benefit automatically.

---

### Standardized Architecture

Large teams need consistency.

Abstract classes enforce structure across hundreds of developers.

# Real Interview Answer

**Q: Why would you use an abstract class in a real project?**

**A:**

> Abstract classes help enforce a common structure across related classes while allowing shared business logic. They are commonly used in payment systems, logging frameworks, Angular base components, notification services, and other enterprise applications where multiple implementations share common behavior but require specific custom implementations.
