
# Object Types in TypeScript

An **Object Type** defines the shape of an object.

### Example

```ts
let user: {
  name: string;
  age: number;
} = {
  name: "Fareed",
  age: 25
};
```

TypeScript ensures:

- Required properties exist.
    
- Property types are correct.
    
- Extra/missing properties are caught.
    

### Quick Revision

- Object types describe an object's structure.
    

# Why Not Use `object`?

### Bad Practice

```ts
let user: object = {
  name: "Fareed",
  age: 25
};
```

Now:

```ts
user.name;
```

❌ Error

Why?

Because `object` only means:

```txt
"some object"
```

TypeScript doesn't know its properties.

### Better

```ts
let user: {
  name: string;
  age: number;
};
```

### Interview Takeaway

> Avoid `object` when you know the shape. Define the structure explicitly.

### Quick Revision

- `object` ❌ Too generic
    
- Explicit shape ✅
    

# Type Inference with Objects

### Preferred

```ts
let user = {
  name: "Fareed",
  age: 25
};
```

TypeScript infers:

```ts
{
  name: string;
  age: number;
}
```

### Good Practice

Use inference when object is initialized immediately.

### Quick Revision

- Let TS infer obvious object types.
    

# Explicit Object Type

### Example

```ts
let user: {
  name: string;
  age: number;
} = {
  name: "Fareed",
  age: 25
};
```

Useful when:

- Variable is declared first.
    
- Object comes later.
    
- API contracts need clarity.
    

### Example

```ts
let user: {
  name: string;
  age: number;
};

user = {
  name: "Fareed",
  age: 25
};
```

### Quick Revision

- Explicit types help when inference isn't possible.
    

# Nested Object Types

### Example

```ts
let employee: {
  id: number;
  address: {
    city: string;
    pincode: number;
  };
} = {
  id: 101,
  address: {
    city: "Chennai",
    pincode: 600001
  }
};
```

### Quick Revision

- Objects can contain other objects.
    

# Optional Properties

### Syntax

```ts
let user: {
  name: string;
  age?: number;
};
```

### Example

```ts
let user = {
  name: "Fareed"
};
```

✅ Valid

```ts
let user2 = {
  name: "Fareed",
  age: 25
};
```

✅ Also Valid

### Quick Revision

- `?` means optional property.
    

# Readonly Properties

### Example

```ts
let user: {
  readonly id: number;
  name: string;
} = {
  id: 101,
  name: "Fareed"
};
```

Later:

```ts
user.id = 102;
```

❌ Error

### Use Cases

- Database IDs
    
- API IDs
    
- Immutable values
    

### Quick Revision

- `readonly` = cannot modify after creation.
    

# Object Type with Arrays

### Example

```ts
let user: {
  name: string;
  skills: string[];
} = {
  name: "Fareed",
  skills: ["React", "TypeScript"]
};
```

### Quick Revision

- Object properties can be arrays.
    

# Object Type with Union Types

### Example

```ts
let employee: {
  id: string | number;
} = {
  id: 101
};
```

Also valid:

```ts
employee.id = "EMP101";
```

### Quick Revision

- Properties can use unions too.
    

# Type Alias (Very Common Interview Topic)

Instead of repeating object structures:

### Bad

```ts
let user1: {
  name: string;
  age: number;
};

let user2: {
  name: string;
  age: number;
};
```

### Better

```ts
type User = {
  name: string;
  age: number;
};
```

Use:

```ts
let user1: User;
let user2: User;
```

### Interview Takeaway

> Type aliases improve reusability and readability.

### Quick Revision

- Repeated object shape → Create a Type Alias.
    

# Function Returning Object Type

### Example

```ts
function createUser(): {
  name: string;
  age: number;
} {
  return {
    name: "Fareed",
    age: 25
  };
}
```

Usually:

```ts
type User = {
  name: string;
  age: number;
};

function createUser(): User {
  return {
    name: "Fareed",
    age: 25
  };
}
```

### Quick Revision

- Use aliases/interfaces for return types.
    

# Common Interview Gotchas

|Question|Answer|
|---|---|
|`object` vs specific object type?|Use specific object type|
|Can TS infer object types?|Yes|
|What does `?` mean?|Optional property|
|What does `readonly` mean?|Cannot be reassigned|
|How to reuse object structures?|Type Alias / Interface|
|Object with mixed property types?|Use unions|
|Nested objects supported?|Yes|
|Preferred for large apps?|Interfaces or Type Aliases|

### Quick Revision

- Avoid generic `object`.
    
- Prefer specific shapes.
    
- Reuse shapes with Type Aliases or Interfaces.
    

# Type Alias vs Inline Object Type

### Inline

```ts
let user: {
  name: string;
  age: number;
};
```

### Type Alias

```ts
type User = {
  name: string;
  age: number;
};

let user: User;
```

### Preferred

```ts
type User = {
  name: string;
  age: number;
};
```

Because:

- Reusable
    
- Cleaner
    
- Easier to maintain
    

### Interview Takeaway

> Inline object types are fine for small examples. In real projects, use Type Aliases or Interfaces.

| Topic                | Quick Recall                                      |
