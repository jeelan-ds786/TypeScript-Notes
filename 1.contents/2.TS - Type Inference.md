

# Type Assignment vs Type Inference

### Type Assignment

When you explicitly assign a type to a variable.

```ts
let userName: string = "fareedh";
let age: number = 25;
let isAdmin: boolean = false;
```

- Developer specifies the type manually.
    
- TypeScript checks future assignments against that type.
    
- Useful when the type is not obvious.
    

### Quick Revision

- `: string`, `: number`, `: boolean` → Explicit Type Assignment
    

# Type Inference

TypeScript automatically determines the type from the assigned value.

```ts
let userName = "fareedh";
```

TypeScript infers:

```ts
let userName: string;
```

Internally.

### Example

```ts
let age = 25;
```

Inferred as:

```ts
let age: number;
```

### Benefits

- Less code.
    
- Cleaner syntax.
    
- Same type safety.
    

### Quick Revision

- TypeScript is smart enough to infer common types.
    

# Which Approach Is Preferred?

### Preferred

```ts
let userName = "fareedh";
```

Why?

- Cleaner code.
    
- No duplicate information.
    
- TypeScript already knows it's a string.
    

### Not Necessary

```ts
let userName: string = "fareedh";
```

- Not wrong.
    
- Just redundant.
    

### Interview Takeaway

> If TypeScript can infer the type correctly, prefer inference over explicit annotations.

### Quick Revision

- Infer when obvious.
    
- Annotate when needed.
    

# `String` vs `string` (Important Interview Trap)

### Wrong

```ts
let userName: String = "fareedh";
```

### Correct

```ts
let userName: string = "fareedh";
```

### Why?

- `string` → Primitive type ✅
    
- `String` → Wrapper Object ❌
    

JavaScript has:

```ts
let a = "hello";              // primitive
let b = new String("hello");  // object
```

TypeScript prefers primitive types.

### Common Interview Trap

|Question|Answer|
|---|---|
|`string` or `String`?|`string`|
|`number` or `Number`?|`number`|
|`boolean` or `Boolean`?|`boolean`|
|Why avoid `String`?|It's an object wrapper type|

### Quick Revision

- Always use lowercase primitive types:
    
    - `string`
        
    - `number`
        
    - `boolean`
        
    - `symbol`
        
    - `bigint`
        

# When Explicit Type Assignment Is Needed

### Function Parameters

```ts
function greet(name: string) {
  return `Hello ${name}`;
}
```

### Variables Without Initial Value

```ts
let userName: string;

userName = "fareedh";
```

### Union Types

```ts
let id: string | number;

id = 101;
id = "EMP101";
```

### Quick Revision

- Use explicit types when TypeScript cannot safely infer.
    

# Interview Answer

**Q: Which is better?**

```ts
let userName: string = "fareedh";
```

or

```ts
let userName = "fareedh";
```

**Answer:**

- Both are valid.
    
- Second approach is generally preferred because TypeScript infers the type automatically.
    
- Use explicit type annotations only when inference is unclear or impossible.
