

# `readonly` in TypeScript

- `readonly` makes a property **assignable only once**
    
- After initialization, its value cannot be changed
    
- Provides compile-time protection (TypeScript error)
    
- Commonly used for IDs, configuration values, immutable data
    
- Quick revision: **readonly = write once, read many times**
    

# Where Can We Use `readonly`?

### Class Properties

```ts
class User {
  readonly id = 101;
}
```

### Constructor Parameter Properties

```ts
class User {
  constructor(readonly id: number) {}
}
```

### Interfaces

```ts
interface User {
  readonly id: number;
}
```

### Type Aliases

```ts
type User = {
  readonly id: number;
};
```

### Arrays

```ts
const numbers: readonly number[] = [1, 2, 3];
```

- Cannot modify array elements
    
- Cannot use `push()`, `pop()`, etc.
    

# Can We Access a `readonly` Property?

✅ Yes

```ts
class User {
  readonly id = 101;
}

const user = new User();

console.log(user.id);
```

Output:

```txt
101
```

### Interview Trap

|Question|Answer|
|---|---|
|Can we read a readonly property?|Yes|
|Can we modify it later?|No|

### Quick Revision

- readonly blocks writing
    
- readonly does NOT block reading
    

# Where Can We Assign a `readonly` Property?

### 1. During Declaration

```ts
class User {
  readonly id = 101;
}
```

### 2. Inside Constructor

```ts
class User {
  readonly id: number;

  constructor(id: number) {
    this.id = id;
  }
}
```

### 3. Using Parameter Properties

```ts
class User {
  constructor(readonly id: number) {}
}
```

### After That ❌

```ts
user.id = 200;
```

Error:

```txt
Cannot assign to 'id' because it is a read-only property.
```

# Can We Declare `readonly` Without Assigning?

✅ Yes, if you assign it in the constructor.

```ts
class User {
  readonly id: number;

  constructor(id: number) {
    this.id = id;
  }
}
```

Valid because constructor initializes it.

# What Happens If We Don't Assign Anywhere?

```ts
class User {
  readonly id: number;
}
```

Error:

```txt
Property 'id' has no initializer and is not definitely assigned.
```

Because TypeScript expects it to be initialized.

# Readonly vs Const

|Feature|readonly|const|
|---|---|---|
|Used on object/class properties|✅|❌|
|Used on variables|❌|✅|
|Value change prevented|✅|✅|
|Object property level|✅|❌|

### Example

```ts
const name = "Fareed";
```

```ts
class User {
  readonly id = 1;
}
```

# Readonly Array

```ts
const nums: readonly number[] = [1, 2, 3];
```

Allowed:

```ts
console.log(nums[0]);
```

Not allowed:

```ts
nums.push(4);
nums[0] = 10;
```

### Interview Question

**Q: Does readonly make array completely immutable?**

**A:** It prevents modifications through that reference, but it is not deep immutability.

# Quick Recall

- `readonly` = assign once
    
- Can be read anytime
    
- Can initialize:
    
    - During declaration
        
    - Inside constructor
        
    - Constructor parameter property
        
- Cannot reassign later
    
- Works in classes, interfaces, types, arrays
    
- Not the same as `const`
    

| Topic              | Quick Recall               |
| ------------------ | -------------------------- |
| readonly           | Write once, read many      |
| Access             | Can read normally          |
| Initialization     | Declaration or constructor |
| Reassignment       | Not allowed                |
| Interface Support  | Yes                        |
| Type Alias Support | Yes                        |
| Readonly Array     | No push/pop/update         |
| readonly vs const  | Property vs variable       |
