
# TypeScript Compiler Options (`tsconfig.json`)

- Controls how TypeScript compiles `.ts` → `.js`
    
- Defined inside `tsconfig.json`
    
- Helps with type safety, module resolution, output generation, and project structure
    
- Interviewers often ask _why a specific compiler option is used_
    
- Quick revision: **Compiler options = rules for TypeScript compilation**
    

# `target`

- Defines JavaScript version generated by TypeScript
    
- Examples: `ES5`, `ES6`, `ES2020`, `ESNext`
    
- Higher target = less transpilation
    
- Lower target = better browser compatibility
    
- Quick revision: **target = output JavaScript version**
    

```json
{
  "compilerOptions": {
    "target": "ES2020"
  }
}
```

# `module`

- Defines module system used in output
    
- Common values:
    
    - `CommonJS` → Node.js
        
    - `ESNext` / `ES6` → Modern frontend apps
        
- Determines how imports/exports are compiled
    
- Quick revision: **module = import/export strategy**
    

```json
{
  "compilerOptions": {
    "module": "ESNext"
  }
}
```

# `strict`

- Enables all strict type-checking rules
    
- Helps catch bugs during development
    
- Recommended for production projects
    
- Includes:
    
    - `strictNullChecks`
        
    - `noImplicitAny`
        
    - `strictFunctionTypes`
        
- Quick revision: **strict = maximum type safety**
    

```json
{
  "compilerOptions": {
    "strict": true
  }
}
```

# `noImplicitAny`

- Prevents variables from automatically becoming `any`
    
- Forces explicit typing when TypeScript cannot infer type
    
- Common interview topic
    
- Quick revision: **Avoids hidden `any` types**
    

```ts
function greet(name) { } // Error
```

# `strictNullChecks`

- Treats `null` and `undefined` as separate types
    
- Prevents runtime null-related bugs
    
- Forces proper null handling
    
- Quick revision: **null must be handled explicitly**
    

```ts
let name: string = null; // Error
```

# `outDir`

- Specifies output folder for compiled JavaScript
    
- Keeps source and build files separate
    
- Commonly used with `dist`
    
- Quick revision: **outDir = build folder**
    

```json
{
  "compilerOptions": {
    "outDir": "./dist"
  }
}
```

# `rootDir`

- Defines source code root directory
    
- Helps maintain folder structure in output
    
- Usually points to `src`
    
- Quick revision: **rootDir = source folder**
    

```json
{
  "compilerOptions": {
    "rootDir": "./src"
  }
}
```

# `sourceMap`

- Generates `.map` files
    
- Allows debugging original TypeScript in browser DevTools
    
- Very common in frontend projects
    
- Quick revision: **sourceMap = debug TS instead of JS**
    

```json
{
  "compilerOptions": {
    "sourceMap": true
  }
}
```

# `removeComments`

- Removes comments from generated JavaScript
    
- Produces cleaner build output
    
- Slightly reduces bundle size
    
- Quick revision: **strip comments during compilation**
    

```json
{
  "compilerOptions": {
    "removeComments": true
  }
}
```

# `allowJs`

- Allows JavaScript files inside TypeScript projects
    
- Useful during migration from JS → TS
    
- Enables gradual adoption
    
- Quick revision: **TS can compile JS too**
    

```json
{
  "compilerOptions": {
    "allowJs": true
  }
}
```

# `checkJs`

- Type-checks JavaScript files
    
- Used together with `allowJs`
    
- Helps find issues before full migration
    
- Quick revision: **Type safety for JS files**
    

```json
{
  "compilerOptions": {
    "checkJs": true
  }
}
```

# `esModuleInterop`

- Improves compatibility between CommonJS and ES Modules
    
- Frequently asked in interviews
    
- Enables easier default imports
    

Without:

```ts
import * as express from "express";
```

With:

```ts
import express from "express";
```

- Quick revision: **Fixes import compatibility issues**
    

# `moduleResolution`

- Determines how TypeScript locates imported modules
    
- Common values:
    
    - `node`
        
    - `bundler`
        
- Important in React/Vite/Webpack projects
    
- Quick revision: **moduleResolution = how imports are found**
    

# `resolveJsonModule`

- Allows importing JSON files directly
    
- Common in frontend configuration files
    
- Quick revision: **Import JSON as modules**
    

```ts
import config from "./config.json";
```

# `skipLibCheck`

- Skips type checking of declaration files (`.d.ts`)
    
- Speeds up compilation
    
- Commonly enabled in large projects
    
- Quick revision: **Faster builds, less library validation**
    

```json
{
  "compilerOptions": {
    "skipLibCheck": true
  }
}
```

# `declaration`

- Generates `.d.ts` files
    
- Useful when publishing libraries/packages
    
- Exposes type definitions to consumers
    
- Quick revision: **Creates TypeScript type declarations**
    

```json
{
  "compilerOptions": {
    "declaration": true
  }
}
```

# Frequently Asked Interview Questions

|Question|Answer|
|---|---|
|What is `tsconfig.json`?|Configuration file that controls TypeScript compilation.|
|Difference between `target` and `module`?|`target` controls JS version generated, `module` controls import/export format.|
|Why use `strict` mode?|Better type safety and early bug detection.|
|What does `noImplicitAny` do?|Prevents automatic `any` type assignment.|
|Why use `strictNullChecks`?|Avoids null/undefined runtime errors.|
|What is `esModuleInterop`?|Enables easier interoperability between CommonJS and ES Modules.|
|Difference between `rootDir` and `outDir`?|`rootDir` = source location, `outDir` = compiled output location.|
|Why use `sourceMap`?|Debug original TypeScript instead of generated JavaScript.|
|What does `skipLibCheck` do?|Skips type checking for third-party declaration files to improve build speed.|
|When would you use `allowJs`?|During gradual migration from JavaScript to TypeScript.|
|Why generate declaration files?|To distribute type definitions when publishing libraries.|
|Difference between `moduleResolution: node` and `bundler`?|`node` follows Node resolution; `bundler` aligns with modern bundlers like Vite/Webpack.|
|Most important compiler options in production?|`strict`, `target`, `module`, `sourceMap`, `esModuleInterop`, `skipLibCheck`.|

# Interview Traps & Gotchas

|Trap Question|Correct Answer|
|---|---|
|Does `strict` only enable one check?|No, it enables multiple strict checks.|
|Does TypeScript run in browser?|No, it compiles to JavaScript first.|
|Does `target` decide module system?|No. `target` and `module` are independent.|
|Is `skipLibCheck` improving type safety?|No. It improves compilation speed.|
|Does `allowJs` make JS files strongly typed?|No. Use `checkJs` for type checking.|
|Is `sourceMap` required in production?|Usually disabled or controlled separately for security/performance reasons.|
|Is `esModuleInterop` mandatory?|No, but many projects enable it for easier imports.|
