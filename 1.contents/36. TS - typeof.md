

# `typeof` in TypeScript

There are **two completely different `typeof`s**.

1. **JavaScript `typeof`** → Runtime operator
    
2. **TypeScript `typeof`** → Type query (compile-time)
    

This distinction is asked in interviews.

---

# 1. JavaScript `typeof` (Runtime)

JavaScript checks the type **while the code is running**.

```ts
console.log(typeof "Hello");
```

Output:

```text
string
```

More examples:

```ts
typeof 100          // "number"
typeof true         // "boolean"
typeof {}           // "object"
typeof []           // "object"
typeof (() => {})   // "function"
typeof undefined    // "undefined"
typeof null         // "object"  ← JavaScript bug
```

### Interview Gotcha

|Expression|Result|
|---|---|
|`typeof []`|`"object"`|
|`typeof null`|`"object"` (historical JavaScript bug)|
|`typeof function(){}`|`"function"`|

---

# 2. TypeScript `typeof` (Compile-Time)

TypeScript's `typeof` **does not run your code**.

It simply asks:

> **"What is the type of this variable?"**

Example:

```ts
const age = 25;

type Age = typeof age;
```

Now:

```ts
type Age = number;
```

No JavaScript is generated.

---

# Example 1 — `let`

```ts
let userName = "Max";

type UserName = typeof userName;
```

What is `UserName`?

```ts
type UserName = string;
```

### Why?

Because `let` variables are mutable.

```ts
let userName = "Max";

userName = "John";
userName = "Alice";
```

Since the value can change, TypeScript widens the type to:

```ts
string
```

---

# Example 2 — `const`

```ts
const userName = "Max";

type UserName = typeof userName;
```

Now the type becomes:

```ts
type UserName = "Max";
```

Notice:

Not `string`.

It is the **string literal type**.

### Why?

Because a `const` variable cannot be reassigned.

```ts
const userName = "Max";

userName = "John"; // ❌ Error
```

Since it can **only ever be `"Max"`**, TypeScript preserves the literal.

---

# Visual Comparison

## `let`

```ts
let name = "Max";
```

TypeScript thinks:

```text
This variable can change.

Today → "Max"
Tomorrow → "John"
Next week → "David"

Therefore:

string
```

---

## `const`

```ts
const name = "Max";
```

TypeScript thinks:

```text
This value can NEVER change.

It is always:

"Max"
```

So the type becomes:

```ts
"Max"
```

---

# Another Example

```ts
let age = 25;

type A = typeof age;
```

Result:

```ts
number
```

---

```ts
const age = 25;

type A = typeof age;
```

Result:

```ts
25
```

Not:

```ts
number
```

Because the value is fixed forever.

---

# Objects

```ts
const user = {
    name: "Max",
    age: 25
};

type User = typeof user;
```

Result:

```ts
type User = {
    name: string;
    age: number;
}
```

Notice something interesting:

Even though `user` is `const`, the properties are still:

```ts
string
number
```

Not:

```ts
"Max"
25
```

### Why?

Because:

```ts
user.name = "John";
```

is allowed.

`const` only prevents reassigning the **variable**, not mutating the object's properties.

---

# `as const` Changes This

```ts
const user = {
    name: "Max",
    age: 25
} as const;
```

Now:

```ts
type User = typeof user;
```

becomes:

```ts
{
    readonly name: "Max";
    readonly age: 25;
}
```

Everything becomes:

- readonly
    
- literal types
    

---

# Real-Time Example

```ts
const roles = ["admin", "teacher"] as const;

type Role = typeof roles[number];
```

Result:

```ts
type Role = "admin" | "teacher";
```

This is used heavily in React, Next.js, and many TypeScript codebases.

# Interview Gotchas

| Question                                      | Answer                                                                                                 |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `typeof` in JavaScript vs TypeScript?         | JavaScript returns a runtime type as a string; TypeScript returns the compile-time type of a variable. |
| `typeof let x = "Max"`                        | `string`                                                                                               |
| `typeof const x = "Max"`                      | `"Max"` (literal type)                                                                                 |
| Why does `const` preserve literals?           | Because the variable cannot be reassigned, so its value is known exactly.                              |
| Does `const` make object properties readonly? | ❌ No. Use `as const` for readonly literal properties.                                                  |
| What does `typeof roles[number]` do?          | Creates a union of all element types in the array.                                                     |

---

# Quick Interview Answer

**Q: Why does `typeof` return different types for `let` and `const`?**

> "`let` variables are mutable, so TypeScript widens their type to a general type like `string` or `number`. `const` variables cannot be reassigned, so TypeScript preserves their exact literal value, such as `'Max'` or `25`. This allows more precise type checking."

---

| Topic               | Quick Recall                                                         |
| ------------------- | -------------------------------------------------------------------- |
| JavaScript `typeof` | Runtime operator returning strings like `"string"` or `"number"`     |
| TypeScript `typeof` | Compile-time operator that extracts a variable's type                |
| `let` + `typeof`    | Produces widened types (`string`, `number`, etc.)                    |
| `const` + `typeof`  | Produces literal types (`"Max"`, `25`, etc.)                         |
| `as const`          | Preserves literal types and makes object/array properties `readonly` |
