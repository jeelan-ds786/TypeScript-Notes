
# Type Aliases

A **Type Alias** gives a custom name to a type.

Think of it as:

```txt
Type Alias = Nickname for a Type
```

### Syntax

```ts
type UserName = string;
```

Now:

```ts
let name: UserName = "Fareed";
```

Here `UserName` is just another name for `string`.

### Quick Revision

- `type` creates a reusable type name.
    

# Why Do We Need Type Aliases?

Without aliases:

```ts
let role: "admin" | "user" | "operator";
let currentRole: "admin" | "user" | "operator";
let assignedRole: "admin" | "user" | "operator";
```

Repeating the same type everywhere.

### Better

```ts
type Role =
  | "admin"
  | "user"
  | "operator";
```

Now:

```ts
let role: Role;
let currentRole: Role;
let assignedRole: Role;
```

### Quick Revision

- Avoid repeating complex types.
    

# Type Alias with Literal Types

This is the most common beginner example.

### Without Alias

```ts
let role:
  | "admin"
  | "user"
  | "operator";
```

### With Alias

```ts
type Role =
  | "admin"
  | "user"
  | "operator";

let role: Role;
```

Benefits:

- Cleaner
    
- Reusable
    
- Easier maintenance
    

### Interview Takeaway

> Type aliases are commonly used to name union types.

### Quick Revision

- Alias + Literal Union = Very common pattern.
    

# Type Alias with Object Types

Without Alias:

```ts
let user: {
  id: number;
  name: string;
  age: number;
};
```

Now imagine using this in 20 places.

### Better

```ts
type User = {
  id: number;
  name: string;
  age: number;
};
```

Usage:

```ts
let user: User;

let admin: User;
```

### Quick Revision

- Object types are the most common use of aliases.
    

# Real React Example

### Without Alias

```ts
function UserCard(props: {
  name: string;
  age: number;
  email: string;
}) {}
```

### Better

```ts
type UserProps = {
  name: string;
  age: number;
  email: string;
};

function UserCard(props: UserProps) {}
```

### Why?

If props change:

```ts
type UserProps = {
  name: string;
  age: number;
  email: string;
  role: string;
};
```

Every component automatically gets updated.

### Quick Revision

- React props often use aliases.
    

# Type Alias with Arrays

### Example

```ts
type UserNames = string[];
```

Usage:

```ts
let names: UserNames = [
  "Fareed",
  "John"
];
```

### Example

```ts
type Scores = number[];
```

### Quick Revision

- Arrays can be aliased too.
    

# Type Alias with Functions

### Example

```ts
type AddFn =
  (a: number, b: number) => number;
```

Usage:

```ts
const add: AddFn =
  (a, b) => a + b;
```

### Benefits

- Reusable function signatures.
    
- Cleaner code.
    

### Quick Revision

- Aliases can describe functions.
    

# Type Alias with Unions

### Example

```ts
type ID = string | number;
```

Usage:

```ts
let userId: ID;

userId = 101;
userId = "EMP101";
```

### Quick Revision

- Very common in APIs.
    

# SOS Example (Why Aliases Help)

Imagine an e-commerce project.

Without aliases:

```ts
let user: {
  id: number;
  name: string;
  role:
    | "admin"
    | "user"
    | "operator";
};
```

Used in:

- Login Page
    
- Dashboard
    
- Admin Panel
    
- Orders Page
    
- Profile Page
    

If role changes:

```ts
| "manager"
```

You must update dozens of places.

### With Alias

```ts
type Role =
  | "admin"
  | "user"
  | "operator";
```

Change once:

```ts
type Role =
  | "admin"
  | "user"
  | "operator"
  | "manager";
```

Entire project updates.

### Interview Takeaway

> Type aliases centralize type definitions, making large applications easier to maintain.

### Quick Revision

- Define once.
    
- Reuse everywhere.
    

# Type Alias vs Interface

### Type Alias

```ts
type User = {
  id: number;
  name: string;
};
```

### Interface

```ts
interface User {
  id: number;
  name: string;
}
```

Both are very similar for object definitions.

### Modern Rule

```txt
Objects      → Interface (often preferred)
Unions       → Type Alias
Functions    → Type Alias
Primitives   → Type Alias
```

### Interview Note

Many companies use both interchangeably.

### Quick Revision

- Interface = Object Shapes
    
- Type Alias = Anything
    

# Common Interview Gotchas

|Question|Answer|
|---|---|
|What is a Type Alias?|Custom name for a type|
|Why use it?|Reusability and maintainability|
|Can aliases describe objects?|Yes|
|Can aliases describe unions?|Yes|
|Can aliases describe arrays?|Yes|
|Can aliases describe functions?|Yes|
|Interface or Type for unions?|Type Alias|
|Does a Type Alias exist in JavaScript output?|No|

### Quick Revision

- Type Alias is a TypeScript-only feature.
    
- It disappears during compilation.
    
- Helps manage complex types in large codebases.
