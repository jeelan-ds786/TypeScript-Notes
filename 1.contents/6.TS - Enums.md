

# Enums in TypeScript

An **Enum** is a way to define a set of named constants.

### Example

```ts
enum Role {
  Admin,
  User,
  Operator
}
```

Internally:

```txt
Admin    = 0
User     = 1
Operator = 2
```

Usage:

```ts
let member: Role = Role.Admin;
```

### Quick Revision

- Enum = Named constant values.
    
- Default numbering starts from `0`.
    

# Why Does This Work?

### Example

```ts
enum Role {
  Admin,
  User,
  Operator
}

let member: Role = 0;
```

✅ Valid

### Why?

Because internally:

```ts
Role.Admin === 0
```

TypeScript numeric enums are compatible with numbers.

```ts
member = 1; // User
member = 2; // Operator
```

Also valid.

### Interview Trap

Many developers expect:

```ts
let member: Role = 100;
```

to fail.

But it may compile depending on TS settings/version because numeric enums are fundamentally numbers.

### Quick Revision

- Numeric enums are not fully type-safe.
    
- They behave like numbers.
    

# What Happens If You Start From 1?

### Example

```ts
enum Role {
  Admin = 1,
  User,
  Operator
}
```

Generated values:

```txt
Admin    = 1
User     = 2
Operator = 3
```

Now:

```ts
let member: Role = 0;
```

### Result

TypeScript may still allow assignment because `Role` is a numeric enum type, but:

```ts
Role[0]
```

returns:

```txt
undefined
```

because no member exists at value `0`.

### Quick Revision

- Starting at 1 removes a valid enum member at 0.
    
- But enum type is still number-based.
    

# Your Example

### TypeScript

```ts
enum Role {
  Admin = 1,
  User,
  Operator
}
```

Values become:

```txt
Admin    = 1
User     = 2
Operator = 3
```

### Runtime Object

```js
{
  1: "Admin",
  2: "User",
  3: "Operator",

  Admin: 1,
  User: 2,
  Operator: 3
}
```

### Example

```ts
console.log(Role.Admin);
```

Output:

```txt
1
```

```ts
console.log(Role[1]);
```

Output:

```txt
Admin
```

### Quick Revision

- Numeric enums support reverse mapping.
    

# How JavaScript Is Generated?

### TypeScript

```ts
enum Role {
  Admin,
  User,
  Operator
}
```

Generated JavaScript:

```js
var Role;

(function (Role) {
    Role[Role["Admin"] = 0] = "Admin";
    Role[Role["User"] = 1] = "User";
    Role[Role["Operator"] = 2] = "Operator";
})(Role || (Role = {}));
```

### Simplified Runtime Object

```js
{
  0: "Admin",
  1: "User",
  2: "Operator",

  Admin: 0,
  User: 1,
  Operator: 2
}
```

### Why?

To support:

```ts
Role.Admin
```

and

```ts
Role[0]
```

Both directions.

### Quick Revision

- Numeric enums create extra JavaScript code.
    
- Forward mapping + reverse mapping.
    

# String Enums

### Example

```ts
enum Role {
  Admin = "ADMIN",
  User = "USER",
  Operator = "OPERATOR"
}
```

Usage:

```ts
let member: Role = Role.Admin;
```

### Invalid

```ts
let member: Role = 0;
```

❌ Error

### Why?

Because enum values are strings, not numbers.

### Generated JS

```js
var Role;

(function (Role) {
    Role["Admin"] = "ADMIN";
    Role["User"] = "USER";
    Role["Operator"] = "OPERATOR";
})(Role || (Role = {}));
```

No reverse mapping.

### Quick Revision

- String enums are safer than numeric enums.
    

# Modern Frontend Recommendation

Instead of:

```ts
enum Role {
  Admin,
  User,
  Operator
}
```

Many React/TypeScript projects prefer:

```ts
type Role =
  | "ADMIN"
  | "USER"
  | "OPERATOR";
```

Usage:

```ts
let role: Role = "ADMIN";
```

### Benefits

- No generated JavaScript.
    
- Smaller bundle size.
    
- Better type safety.
    
- Easier API integration.
    

### Interview Takeaway

> Modern TypeScript codebases often prefer string unions over enums unless reverse mapping or enum semantics are specifically needed.

# Common Interview Gotchas

|Question|Answer|
|---|---|
|Default enum value starts at?|`0`|
|Can `let role: Role = 0` work?|Yes, for numeric enums|
|Why?|Numeric enums are number-based|
|Does `Role.Admin` equal `0`?|Yes (default enum)|
|What if enum starts at 1?|Members become 1,2,3...|
|Does numeric enum generate JS?|Yes|
|Does string enum generate JS?|Yes|
|Do union types generate JS?|No|
|Preferred in modern React apps?|String unions often preferred|

### Quick Revision

- Numeric Enum → Number-based, reverse mapping.
    
- String Enum → Safer, readable values.
    
- Union Type → Zero runtime cost, common in frontend apps.
