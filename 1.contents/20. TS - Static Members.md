

# Static Properties & Methods in TypeScript

- `static` means the property/method belongs to the **class itself**
    
- Not tied to any object (instance)
    
- Memory is allocated only once for the class
    
- Can be accessed without creating an object
    
- Quick revision: **static = class-level member**
    

# Why Can We Call It Without Creating an Object?

Normal property:

```ts
class User {
  name = "Fareed";
}

const user = new User();

console.log(user.name);
```

Here `name` belongs to each object.

---

Static property:

```ts
class User {
  static company = "Google";
}

console.log(User.company);
```

Here `company` belongs to the class itself.

Memory visualization:

```txt
User Class
 ├── static company = "Google"
 └── constructor()

user1 object
 └── name

user2 object
 └── name
```

Only one copy of `company` exists.

# Static Method Example

```ts
class MathUtil {
  static add(a: number, b: number) {
    return a + b;
  }
}

console.log(MathUtil.add(10, 20));
```

No object needed.

```ts
const obj = new MathUtil();

obj.add(10, 20); // ❌ Error
```

### Interview Trap

|Question|Answer|
|---|---|
|Can static methods be called via object?|No|
|Can static methods be called via class?|Yes|

### Quick Recall

- `ClassName.method()`
    
- Not `object.method()`
    

# Why Was Static Introduced?

Imagine this:

```ts
class MathUtil {
  add(a: number, b: number) {
    return a + b;
  }
}
```

To use it:

```ts
const math = new MathUtil();

math.add(1, 2);
```

Creating an object just to add numbers is unnecessary.

Instead:

```ts
class MathUtil {
  static add(a: number, b: number) {
    return a + b;
  }
}

MathUtil.add(1, 2);
```

Cleaner and faster.

# Real Industry Examples

## Utility Classes

```ts
class DateUtils {
  static formatDate(date: Date) {
    return date.toISOString();
  }
}
```

Usage:

```ts
DateUtils.formatDate(new Date());
```

Common in enterprise projects.

## Configuration Values

```ts
class AppConfig {
  static API_URL =
    "https://api.company.com";
}
```

Usage:

```ts
fetch(AppConfig.API_URL);
```

One shared value across application.

## Constants

```ts
class Roles {
  static ADMIN = "ADMIN";
  static USER = "USER";
}
```

Usage:

```ts
if (role === Roles.ADMIN) {
}
```

Avoids magic strings.

## Factory Methods

```ts
class User {
  constructor(
    public name: string
  ) {}

  static createGuest() {
    return new User("Guest");
  }
}
```

Usage:

```ts
const guest = User.createGuest();
```

Very common in backend and frontend systems.

# Static vs Instance Members

```ts
class User {
  static company = "Google";

  name = "Fareed";
}
```

Usage:

```ts
console.log(User.company); // ✅

const user = new User();

console.log(user.name); // ✅
```

Not allowed:

```ts
console.log(user.company);
```

Error ❌

### Comparison

|Member Type|Belongs To|Accessed Via|
|---|---|---|
|Static|Class|`User.company`|
|Instance|Object|`user.name`|

# Static Inside Static Methods

```ts
class User {
  static company = "Google";

  static printCompany() {
    console.log(User.company);
  }
}
```

Notice:

```ts
User.company
```

Not:

```ts
this.company
```

(Though `this` works in many cases, interviewers prefer explicit class reference.)

# Common Interview Questions

|Question|Answer|
|---|---|
|Why use static?|Shared data and utility functions|
|Is object creation required?|No|
|Where is static stored?|On the class itself|
|How many copies exist?|One|
|Can instance access static directly?|No|
|Can static access instance properties?|No|

# Important Interview Trap

```ts
class User {
  name = "Fareed";

  static print() {
    console.log(this.name);
  }
}
```

❌ Error

Why?

- Static methods belong to the class
    
- `name` belongs to objects
    
- Static members cannot directly access instance members
    

Correct:

```ts
class User {
  static company = "Google";

  static print() {
    console.log(User.company);
  }
}
```

# React/Frontend Interview Example

```ts
class API {
  static BASE_URL =
    "https://api.company.com";
}
```

```ts
fetch(`${API.BASE_URL}/users`);
```

Why static?

- Same URL for entire application
    
- No need to create API objects everywhere
