
# Getters and Setters in TypeScript

- Getters and setters allow controlled access to class properties
    
- Used for validation, formatting, computed values, encapsulation
    
- Accessed like normal properties, but methods run behind the scenes
    
- TypeScript inherits this feature from JavaScript
    
- Quick revision: **Getter = read logic, Setter = write logic**
    

# Basic Example

```ts
class User {
  private _name = "";

  get name() {
    return this._name;
  }

  set name(value: string) {
    this._name = value;
  }
}

const user = new User();

user.name = "Fareed"; // setter called
console.log(user.name); // getter called
```

### What Happens?

```txt
user.name = "Fareed"
     ↓
Setter executes

console.log(user.name)
     ↓
Getter executes
```

# Why Use Getters and Setters?

### Validation

```ts
class User {
  private _age = 0;

  set age(value: number) {
    if (value < 0) {
      throw new Error("Age cannot be negative");
    }

    this._age = value;
  }

  get age() {
    return this._age;
  }
}
```

- Prevent invalid data from entering object
    

### Computed Values

```ts
class Rectangle {
  constructor(
    public width: number,
    public height: number
  ) {}

  get area() {
    return this.width * this.height;
  }
}

const rect = new Rectangle(10, 20);

console.log(rect.area);
```

Notice:

```ts
rect.area
```

Not:

```ts
rect.area()
```

### Interview Recall

- Getter behaves like property
    
- Getter is called without parentheses
    

# Are Getters and Setters Only in TypeScript?

❌ No

✅ They already exist in JavaScript

JavaScript Example:

```js
class User {
  constructor() {
    this._name = "";
  }

  get name() {
    return this._name;
  }

  set name(value) {
    this._name = value;
  }
}
```

TypeScript simply adds type safety:

```ts
class User {
  private _name = "";

  get name(): string {
    return this._name;
  }

  set name(value: string) {
    this._name = value;
  }
}
```

### Interview Question

**Q: Are getters/setters a TypeScript feature?**

**A:** No. They are a JavaScript feature. TypeScript only adds type checking around them.

# Getter Only (Read-Only Property)

```ts
class User {
  private _id = 101;

  get id() {
    return this._id;
  }
}
```

```ts
console.log(user.id);
```

Allowed ✅

```ts
user.id = 200;
```

Error ❌

Because no setter exists.

### Interview Recall

- Getter only = effectively read-only from outside
    

# Setter Only

```ts
class User {
  private _password = "";

  set password(value: string) {
    this._password = value;
  }
}
```

Allowed:

```ts
user.password = "secret";
```

Not allowed:

```ts
console.log(user.password);
```

Because getter doesn't exist.

# Common Interview Questions

|Question|Answer|
|---|---|
|Why use getters and setters?|Validation, encapsulation, computed values|
|Are they TypeScript-only?|No, JavaScript supports them too|
|How is getter called?|Like a property (`user.name`)|
|How is setter called?|Assignment (`user.name = "Fareed"`)|
|Can a getter exist without setter?|Yes|
|Can a setter exist without getter?|Yes|
|Why use a private backing field like `_name`?|To avoid infinite recursion|

# Interview Trap

|Trap Question|Correct Answer|
|---|---|
|Do we call getter using `()`?|No|
|Are getters normal methods?|They are methods but accessed like properties|
|Can getter accept parameters?|No|
|Can setter return a value?|No|
|Can setter have multiple parameters?|No, exactly one parameter|
|Are getters/setters compiled away by TS?|No, JavaScript supports them natively|

# Common Gotcha (Infinite Recursion)

❌ Wrong

```ts
class User {
  get name() {
    return this.name;
  }
}
```

This calls itself forever.

✅ Correct

```ts
class User {
  private _name = "";

  get name() {
    return this._name;
  }
}
```

Use a separate backing field (`_name`).

# Quick Recall

- Getter = read logic
    
- Setter = write logic
    
- Available in JavaScript and TypeScript
    
- Accessed like properties, not methods
    
- Used for validation and encapsulation
    
- Getter only → read-only externally
    
- Setter only → write-only externally
    
- Backing field (`_name`) avoids recursion
