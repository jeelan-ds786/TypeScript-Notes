

# Generic Types

- **Generics** let you write reusable code that works with **different types** while maintaining type safety.
    
- Instead of hardcoding a type (`string`, `number`), you use a **type placeholder** (usually `T`).
    
- The actual type is supplied **when the function, class, or interface is used**.
    
- Eliminates duplicate code for different types.
    

**Quick Revision:**

> **Generics = Write once, use with many types.**

### Without Generics

You need separate functions for each type.

```ts
function getFirstString(arr: string[]): string {
  return arr[0];
}

function getFirstNumber(arr: number[]): number {
  return arr[0];
}
```

This doesn't scale well.

### With Generics

```ts
function getFirst<T>(arr: T[]): T {
  return arr[0];
}
```

Usage:

```ts
getFirst<string>(["A", "B"]);
getFirst<number>([10, 20]);
getFirst<boolean>([true, false]);
```

Or let TypeScript infer the type:

```ts
getFirst(["A", "B"]);      // T = string
getFirst([1, 2]);          // T = number
```

# Why are Generics Special?

Generics are powerful because they provide:

### 1. Reusability

One function works for many types.

```ts
function identity<T>(value: T): T {
    return value;
}
```

Instead of writing:

- `identityString()`
    
- `identityNumber()`
    
- `identityBoolean()`
    

### 2. Type Safety

```ts
function identity<T>(value: T): T {
    return value;
}

const x = identity("Hello");
// x is string
```

No casting needed.

### 3. Better IntelliSense

```ts
const name = identity("Fareed");
```

VS Code knows:

```ts
name.toUpperCase();
```

because it inferred `string`.

### 4. Flexible APIs

Libraries like:

- React
    
- Redux Toolkit
    
- Axios
    
- React Query
    

all use generics extensively.

Example:

```ts
const users = useState<User[]>([]);
```

The hook works for **any** state type.

# `Array<string>` vs `string`

This is a very common interview question.

### `string`

Represents **one string value**.

```ts
let name: string = "Fareed";
```

Type:

```
string
```

### `Array<string>`

Represents an **array of strings**.

```ts
let names: Array<string> = [
    "Fareed",
    "John",
    "Alice"
];
```

Equivalent to:

```ts
let names: string[];
```

Both are exactly the same.

```ts
Array<string>
```

=

```ts
string[]
```

# Why Does `Array` Use Generics?

The definition is roughly:

```ts
interface Array<T> {
    length: number;
    push(item: T): number;
    pop(): T | undefined;
}
```

When you write:

```ts
Array<string>
```

TypeScript replaces `T` with `string`.

So it becomes conceptually:

```ts
interface Array {
    push(item: string): number;
    pop(): string | undefined;
}
```

Similarly:

```ts
Array<number>
```

becomes:

```ts
push(item: number)
```

This is why generics make built-in types like `Array`, `Promise`, and `Map` reusable.

# Real-Time Examples

### Promise

```ts
Promise<string>
```

means:

```ts
const result: Promise<string>;
```

The resolved value is a `string`.

---

### Map

```ts
Map<string, number>
```

means:

- Key → string
    
- Value → number
    

```ts
const marks = new Map<string, number>();
```

---

### React State

```ts
const [users, setUsers] = useState<User[]>([]);
```

Here:

```
T = User[]
```

The same `useState` function works for:

- string
    
- number
    
- boolean
    
- objects
    
- arrays
    

# Interview Gotchas

|Question|Answer|
|---|---|
|What is a generic?|A placeholder type that is replaced with a real type when used.|
|Why use generics?|Reusability, type safety, and better type inference.|
|Is `Array<string>` different from `string[]`?|❌ No. They are equivalent.|
|Does a generic decide its type at declaration?|❌ No. The type is provided or inferred when the generic is used.|
|Which built-in types use generics?|`Array<T>`, `Promise<T>`, `Map<K, V>`, `Set<T>`, `Record<K, V>`, etc.|

# Is a Generic Parameter Optional?

## Case 1: TypeScript can infer the type ✅

The generic argument is **optional** because TypeScript infers it.

```
function identity<T>(value: T): T {    return value;}identity("Hello");   // T is inferred as stringidentity(100);       // T is inferred as numberidentity(true);      // T is inferred as boolean
```

You don't need to write:

```
identity<string>("Hello");
```

because the compiler already knows `T = string`.
