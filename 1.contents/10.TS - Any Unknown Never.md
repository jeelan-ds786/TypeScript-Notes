
# `{}` Type (Empty Object Type)

This is one of the most confusing TypeScript topics.

### Example

```ts
let userName: {};
```

Most beginners think:

```txt
Only empty objects allowed
```

❌ Wrong

---

### What `{}` Actually Means

```ts
let val: {};

val = "fareed";
val = 100;
val = true;
val = [];
val = {};
```

✅ All valid

Why?

Because `{}` means:

```txt
Any non-nullish value
```

It accepts:

- string
    
- number
    
- boolean
    
- array
    
- object
    

But not:

```ts
val = null;
val = undefined;
```

❌ Invalid

### Interview Takeaway

> `{}` does NOT mean "empty object". It means any value except `null` and `undefined`.

### Quick Revision

- `{}` is rarely useful.
    
- Avoid it in real projects.
    

# `object` vs `{}`

### object

```ts
let value: object;

value = {};
value = [];
```

✅

```ts
value = "hello";
```

❌

### `{}`

```ts
let value: {};

value = {};
value = [];
value = "hello";
value = 100;
```

✅

### Comparison

|Type|Allows String|Allows Number|Allows Object|
|---|---|---|---|
|`object`|❌|❌|✅|
|`{}`|✅|✅|✅|

### Quick Revision

- `object` = object values only.
    
- `{}` = almost everything.
    

# Record Type

Used to define objects with dynamic keys.

### Syntax

```ts
Record<KeyType, ValueType>
```

### Example

```ts
let users:
  Record<string, number>;
```

Meaning:

```txt
Key   → string
Value → number
```

### Usage

```ts
let users: Record<string, number> = {
  fareed: 101,
  john: 102,
  alex: 103
};
```

### Quick Revision

- Dictionary-like objects.
    

# Record Type Real Example

### API Cache

```ts
type User = {
  id: number;
  name: string;
};

const cache:
  Record<string, User> = {
    user1: {
      id: 1,
      name: "Fareed"
    }
  };
```

### Interview Takeaway

> Record is commonly used for lookup tables, caches, maps, and dictionaries.

### Quick Revision

- Dynamic keys → Record.
    

# `void` Type

Means:

```txt
Function returns nothing useful
```

### Example

```ts
function logMessage(): void {
  console.log("Hello");
}
```

### Quick Revision

- `void` = no meaningful return value.
    

# `never` Type

Means:

```txt
This function never finishes normally.
```

### Example 1

Throws Error

```ts
function throwError(): never {
  throw new Error("Oops");
}
```

Function never reaches the end.

---

### Example 2

Infinite Loop

```ts
function forever(): never {
  while (true) {}
}
```

Function never returns.

### Quick Revision

- `never` = impossible to return.
    

# `void` vs `never`

### Void

```ts
function log(): void {
  console.log("Hello");
}
```

Execution completes.

---

### Never

```ts
function crash(): never {
  throw new Error();
}
```

Execution never completes normally.

### Comparison

|Type|Returns?|Function Completes?|
|---|---|---|
|`void`|Nothing|Yes|
|`never`|Nothing|No|

### Interview Takeaway

> `void` means no return value. `never` means execution never reaches the end.

### Quick Revision

- `void` → returns nothing.
    
- `never` → never returns.
    

# `any` Type

Disables TypeScript checking.

### Example

```ts
let value: any;

value = 100;
value = "fareed";
value = true;
```

Everything allowed.

Even:

```ts
value.toUpperCase();
```

No compiler error.

### Danger

Runtime crash possible.

### Quick Revision

- `any` turns TypeScript off.
    

# `unknown` Type

Safer version of `any`.

### Example

```ts
let value: unknown;

value = 100;
value = "fareed";
value = true;
```

Assignments allowed.

But:

```ts
value.toUpperCase();
```

❌ Error

Why?

TypeScript doesn't know what value is.

### Quick Revision

- Unknown accepts anything.
    
- Doesn't allow unsafe usage.
    

# How Unknown Protects You

### Example

```ts
let value: unknown;

value = "fareed";
```

Cannot do:

```ts
value.toUpperCase();
```

❌

Need check first:

```ts
if (typeof value === "string") {
  value.toUpperCase();
}
```

✅

Now TypeScript knows:

```txt
value is string
```

### Quick Revision

- Unknown requires type narrowing.
    

# Type Narrowing with Unknown

### String Check

```ts
if (typeof value === "string") {
  value.toUpperCase();
}
```

### Number Check

```ts
if (typeof value === "number") {
  value.toFixed(2);
}
```

### Array Check

```ts
if (Array.isArray(value)) {
  value.length;
}
```

### Interview Takeaway

> Unknown forces you to prove the type before using it.

### Quick Revision

- Unknown = Safe Any.
    

# Any vs Unknown

### Example

```ts
let value: any;

value.toUpperCase();
```

✅ Compiler allows.

---

### Example

```ts
let value: unknown;

value.toUpperCase();
```

❌ Compiler blocks.

### Comparison

|Feature|any|unknown|
|---|---|---|
|Accept Any Value|✅|✅|
|Access Properties Directly|✅|❌|
|Call Methods Directly|✅|❌|
|Requires Type Checks|❌|✅|
|Type Safe|❌|✅|

### Interview Takeaway

> Prefer `unknown` over `any` whenever possible.

### Quick Revision

- `any` = No safety.
    
- `unknown` = Safety first.
