# Type Casting (Type Assertion) in TypeScript

Type Casting tells TypeScript:

```txt
"I know more about this value than you do."
```

TypeScript's official term is:

```txt
Type Assertion
```

### Example

```ts
let value: unknown = "Fareed";

let userName = value as string;
```

Now TypeScript treats `userName` as:

```ts
string
```

### Quick Revision

- Type Casting = Type Assertion
    
- Used when TypeScript cannot infer the correct type.
    

# Why Do We Need Type Casting?

### Example

```ts
let value: unknown = "Fareed";
```

TypeScript only knows:

```txt
unknown
```

Cannot do:

```ts
value.toUpperCase();
```

❌ Error

### Cast It

```ts
let userName = value as string;

console.log(userName.toUpperCase());
```

✅

### Quick Revision

- Cast when TS knows less than you do.
    

# Syntax 1 (Preferred)

### `as` Syntax

```ts
let userName = value as string;
```

Most common in modern TypeScript.

### Example

```ts
const input =
  document.getElementById("name")
  as HTMLInputElement;
```

### Quick Revision

- Use `as Type`.
    

# Syntax 2 (Older Syntax)

### Angle Brackets

```ts
let userName =
  <string>value;
```

### Example

```ts
let value: unknown = "Fareed";

let userName =
  <string>value;
```

### Why Avoid?

In React/TSX:

```tsx
<string>value
```

looks like JSX.

Causes conflicts.

### Interview Takeaway

> Prefer `as` syntax over angle brackets.

### Quick Revision

- `<Type>` works.
    
- `as Type` preferred.
    

# DOM Example (Most Common Interview Topic)

### Problem

```ts
const input =
  document.getElementById("name");
```

TypeScript infers:

```ts
HTMLElement | null
```

Cannot do:

```ts
input.value;
```

❌ Error

Because generic HTMLElement doesn't have `value`.

---

### Cast

```ts
const input =
  document.getElementById("name")
  as HTMLInputElement;
```

Now:

```ts
input.value;
```

✅

### Quick Revision

- Commonly used with DOM APIs.
    

# Type Casting vs Type Conversion

Very Important Interview Question.

### Type Casting

Only TypeScript compiler is affected.

```ts
let value = "100" as unknown as number;
```

Runtime value:

```txt
"100"
```

Still a string!

---

### Type Conversion

Actually changes the value.

```ts
Number("100");
```

Result:

```txt
100
```

Number.

### Comparison

| Type Casting         | Type Conversion |
| -------------------- | --------------- |
| Compile Time         | Runtime         |
| TS Only              | JS Operation    |
| Doesn't Change Value | Changes Value   |

### Interview Takeaway

> Type assertions do not modify runtime values.

### Quick Revision

- Cast ≠ Convert.
    

# Dangerous Type Casting

### Example

```ts
let value = "Fareed";

let age =
  value as unknown as number;
```

TypeScript accepts it.

But:

```ts
console.log(age + 10);
```

Runtime:

```txt
Fareed10
```

Unexpected result.

### Why?

Because actual value is still string.

### Quick Revision

- Type assertions can lie to TypeScript.
    

# Double Casting

### Example

```ts
let value = "Fareed";

let age =
  value as unknown as number;
```

Why?

TypeScript blocks:

```ts
value as number;
```

because types are unrelated.

Developers bypass it using:

```ts
as unknown as
```

### Interview Takeaway

> Double casting should be avoided unless absolutely necessary.

### Quick Revision

- `as unknown as` = escape hatch.
    

# Non-Null Assertion vs Type Casting

### Type Casting

```ts
const input =
  document.getElementById("name")
  as HTMLInputElement;
```

Changes type.

---

### Non-Null Assertion

```ts
const input =
  document.getElementById("name")!;
```

Removes:

```ts
null
```

from type.

### Combined

```ts
const input =
  document.getElementById("name")
  as HTMLInputElement;
```

or

```ts
const input =
  document.getElementById("name")
  as HTMLInputElement | null;
```

depending on safety needs.

### Quick Revision

- `as` → change type.
    
- `!` → remove null/undefined.
    

# Better Alternative: Type Narrowing

Instead of:

```ts
const input =
  document.getElementById("name")
  as HTMLInputElement;
```

Safer:

```ts
const input =
  document.getElementById("name");

if (input instanceof HTMLInputElement) {
  console.log(input.value);
}
```

Now TypeScript narrows automatically.

### Interview Takeaway

> Prefer narrowing when possible. Cast only when necessary.

### Quick Revision

- Narrowing > Casting.
