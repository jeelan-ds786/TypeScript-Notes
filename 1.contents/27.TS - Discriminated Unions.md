

# Discriminated Union

- A Discriminated Union is a union of types that share a **common property** (called the discriminator)
    
- TypeScript uses that property to automatically narrow the type
    
- Very common in React, Redux, API states, and state machines
    
- Quick revision: **Discriminator = unique field that identifies the type**
    

---

# Problem Without Discriminated Union

```ts
type SuccessResponse = {
  data: string[];
};

type ErrorResponse = {
  error: string;
};

type Response =
  | SuccessResponse
  | ErrorResponse;
```

Now TypeScript doesn't immediately know:

```ts
response.data;
```

❌ Error

Because response could be ErrorResponse.

---

# Solution: Add a Common Identifier

```ts
type SuccessResponse = {
  status: "success";
  data: string[];
};

type ErrorResponse = {
  status: "error";
  error: string;
};
```

```ts
type Response =
  | SuccessResponse
  | ErrorResponse;
```

Notice:

```txt
status
```

exists in every type.

This is the **discriminator**.

---

# How It Works

```ts
function handleResponse(
  response: Response
) {
  if (response.status === "success") {
    console.log(response.data);
  } else {
    console.log(response.error);
  }
}
```

### TypeScript Thinking

```txt
response.status === "success"
          ↓
response must be SuccessResponse
          ↓
data is safe
```

Else:

```txt
response.status === "error"
          ↓
response must be ErrorResponse
          ↓
error is safe
```

No type guards needed.

# Real-Time Example: API Calls

```ts
type Loading = {
  status: "loading";
};

type Success = {
  status: "success";
  users: string[];
};

type Error = {
  status: "error";
  message: string;
};
```

```ts
type ApiState =
  | Loading
  | Success
  | Error;
```

Usage:

```ts
function render(state: ApiState) {
  switch (state.status) {
    case "loading":
      console.log("Loading...");
      break;

    case "success":
      console.log(state.users);
      break;

    case "error":
      console.log(state.message);
      break;
  }
}
```

### Industry Usage

```txt
API Request
     ↓
Loading
     ↓
Success OR Error
```

This pattern is everywhere in React apps.

```ts
type State =

    }

    }
  | {
      status: "success";
      data: string[];
    }
  | {
      status: "error";
      error: string;
    };
```

Reducer:

```ts
if (state.status === "success") {
  state.data;
}
```

TypeScript automatically knows:

```txt
state = Success State
```

# Why Not Use Boolean Flags?

Many beginners write:

```ts
{
  loading: boolean;
  error: boolean;
  data?: string[];
}
```

Problem:

```ts
{
  loading: true,
  error: true
}
```

😵 Invalid business state.

Discriminated Union prevents impossible states.

```ts
{
  status: "loading"
}
```

OR

```ts
{
  status: "success"
}
```

OR

```ts
{
  status: "error"
}
```

Only one valid state at a time.

# Shape Example (Very Common Interview Question)

```ts
type Circle = {
  kind: "circle";
  radius: number;
};

type Rectangle = {
  kind: "rectangle";
  width: number;
  height: number;
};

type Shape =
  | Circle
  | Rectangle;
```

```ts
function area(shape: Shape) {
  switch (shape.kind) {
    case "circle":
      return Math.PI * shape.radius ** 2;

    case "rectangle":
      return shape.width * shape.height;
  }
}
```

### TypeScript Knows

```txt
kind === "circle"
      ↓
shape is Circle
```

# Why Companies Love Discriminated Unions

### Safer State Management

```txt
Loading
Success
Error
```

No impossible combinations.

### Better Autocomplete

```txt
status === "success"
        ↓
TS suggests only success fields
```

### Fewer Runtime Bugs

TypeScript catches mistakes during development.

### Used In

- React
    
- Redux Toolkit
    
- React Query
    
- XState
    
- API clients
    
- Form handling
    
- Payment workflows

# Interview Questions

|Question|Answer|
|---|---|
|What is a Discriminated Union?|Union types sharing a common literal property|
|What is the discriminator?|Common property like `status`, `type`, `kind`|
|Why use it?|Safe type narrowing|
|Common use case?|API states, Redux states|
|Better than boolean flags?|Yes, prevents invalid states|
|Does it require custom type guards?|Usually no|

# Interview Trap

|Trap Question|Correct Answer|
|---|---|
|Is discriminator any string field?|No, usually a literal type field|
|Can TS narrow automatically?|Yes|
|Is it only for React?|No|
|Does it exist at runtime?|No, TS uses it for type checking|

# Quick Recall

- Discriminated Union = Union + common identifier
    
- Common fields:
    
    - `status`
        
    - `type`
        
    - `kind`
        
- TypeScript automatically narrows types
    
- Used heavily in React and Redux
    
- Prevents impossible states
    
- Cleaner than multiple boolean flags
