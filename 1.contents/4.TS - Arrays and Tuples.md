

# Arrays in TypeScript

An **Array** stores multiple values of the **same type**.

### Syntax 1 (Most Common)

```ts
let numbers: number[] = [1, 2, 3];
let names: string[] = ["Fareed", "John"];
```

### Syntax 2 (Generic Style)

```ts
let numbers: Array<number> = [1, 2, 3];
let names: Array<string> = ["Fareed", "John"];
```

Both are exactly the same.

### Quick Revision

- `number[]` ✅
    
- `Array<number>` ✅
    
- Same meaning, different syntax.
    

# Why Two Syntaxes?

### Traditional Array Syntax

```ts
let users: string[] = ["A", "B"];
```

Short and readable.

### Generic Syntax

```ts
let users: Array<string> = ["A", "B"];
```

Useful when working with Generics.

### Interview Takeaway

> Most frontend teams prefer `string[]` because it is shorter and easier to read.

### Quick Revision

- Prefer `string[]` in everyday code.
    
- `Array<T>` often appears in generic-heavy code.
    

# Mixed Arrays Using Union Types

### Example

```ts
let values: (string | number)[] = [
  "Fareed",
  101,
  "Admin"
];
```

Valid:

```ts
values.push(200);
values.push("Manager");
```

### Quick Revision

- `(string | number)[]`
    
- Array elements can be either type.
    

# Type Inference with Arrays

### Example

```ts
let names = ["Fareed", "John"];
```

TypeScript infers:

```ts
string[]
```

### Example

```ts
let scores = [10, 20, 30];
```

Inferred as:

```ts
number[]
```

### Preferred Approach

```ts
let names = ["Fareed", "John"];
```

Instead of:

```ts
let names: string[] = [
  "Fareed",
  "John"
];
```

when the type is obvious.

### Quick Revision

- Let TypeScript infer obvious array types.
    

# Tuples in TypeScript

A **Tuple** is a fixed-length array where each position has a predefined type.

### Example

```ts
let employee: [number, string];
```

Meaning:

```txt
Position 1 → number
Position 2 → string
```

### Usage

```ts
let employee: [number, string] =
  [101, "Fareed"];
```

✅ Valid

```ts
let employee: [number, string] =
  ["Fareed", 101];
```

❌ Error

### Quick Revision

- Array → Same type
    
- Tuple → Fixed positions and types
    

# Real-World Tuple Examples

### API Response

```ts
let response: [number, string];
```

```ts
response = [200, "Success"];
```

Meaning:

```txt
Status Code
Message
```

### Coordinate System

```ts
let point: [number, number];
```

```ts
point = [10, 20];
```

Meaning:

```txt
x-coordinate
y-coordinate
```

### Quick Revision

- Tuples represent structured data with fixed positions.
    

# Array vs Tuple

|Feature|Array|Tuple|
|---|---|---|
|Length|Dynamic|Fixed|
|Types|Usually Same|Can Be Different|
|Position Matters|No|Yes|
|Use Case|List of Data|Structured Data|
|Example|Users List|[id, name]|

### Example Array

```ts
let names: string[] =
["A", "B", "C"];
```

### Example Tuple

```ts
let user: [number, string] =
[101, "Fareed"];
```

### Interview Takeaway

> Use arrays for collections. Use tuples for fixed structured values.

# Good Practices

### ✅ Use Inference When Obvious

```ts
let names = ["A", "B"];
```

Better than:

```ts
let names: string[] = ["A", "B"];
```

when the type is already clear.

### ✅ Use Explicit Types for APIs

```ts
let users: User[] = [];
```

Improves readability.

### ✅ Use Tuples Sparingly

```ts
let user: [number, string];
```

Good for:

- Coordinates
    
- API status pairs
    
- Key-value pairs
    

### ❌ Avoid Large Tuples

```ts
let user: [
  number,
  string,
  string,
  boolean,
  number
];
```

Hard to understand.

Prefer:

```ts
interface User {
  id: number;
  name: string;
  email: string;
  active: boolean;
}
```

### Quick Revision

- Small structured data → Tuple
    
- Complex structured data → Interface
