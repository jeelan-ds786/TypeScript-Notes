
# Function Overloading (TypeScript)

- **Function Overloading** allows a function to have **multiple call signatures** with different parameter types or counts.
    
- Only **one actual implementation** exists.
    
- The implementation must be compatible with **all overload signatures**.
    
- Improves **type safety**, **IntelliSense**, and **developer experience**.
    
- **JavaScript does NOT support function overloading**. This is a **TypeScript compile-time feature**.
    

### Syntax

```ts
// Overload Signatures
function greet(name: string): string;
function greet(age: number): string;

// Implementation
function greet(value: string | number): string {
    if (typeof value === "string") {
        return `Hello ${value}`;
    }
    return `You are ${value} years old`;
}

greet("Fareed"); // Hello Fareed
greet(25);       // You are 25 years old
```

### Why is Function Overloading Powerful?

- Provides **different APIs** using the same function name.
    
- Gives **better autocomplete** in editors.
    
- Eliminates unnecessary type casting.
    
- Makes library APIs cleaner and easier to use.
    
- Ensures invalid argument combinations are caught at compile time.
    

**Quick Revision:**

> Same function name + Multiple call signatures + One implementation.

### Real-Time Examples

#### 1. Search API

```ts
function search(id: number): User;
function search(name: string): User[];

function search(value: number | string) {
    if (typeof value === "number") {
        return getUserById(value);
    }
    return searchUsers(value);
}
```

**Interview Use Case**

- Search by **ID**
    
- Search by **Name**
    
- Same function, different behavior.
    

#### 2. HTTP Client

```ts
function request(url: string): Response;
function request(url: string, config: Config): Response;

function request(url: string, config?: Config) {
    // implementation
}
```

Common in libraries like:

- Axios
    
- Fetch wrappers
    
- Angular HttpClient
    

#### 3. Date Formatter

```ts
function format(date: Date): string;
function format(timestamp: number): string;

function format(value: Date | number) {
    return new Date(value).toLocaleDateString();
}
```

Users can pass:

- Date object
    
- Timestamp
    

### Function Overloading vs Union Types

|Question|Function Overloading|Union Type|
|---|---|---|
|Multiple call signatures|✅ Yes|❌ No|
|Better IntelliSense|✅ Excellent|⚠️ Limited|
|Different return types|✅ Yes|❌ Usually same return type|
|Best for public APIs|✅ Yes|⚠️ Sometimes|
|Simpler implementation|❌ More code|✅ Less code|

**Interview Rule:**

- Use **Union Types** when behavior is almost identical.
    
- Use **Function Overloading** when parameter combinations or return types differ.
    

### Interview Gotchas

|Question|Answer|
|---|---|
|Can JavaScript do function overloading?|❌ No. Later function declarations overwrite earlier ones.|
|How many implementations are allowed?|Exactly **one**.|
|Can overload signatures contain implementation?|❌ No. Only declarations.|
|Which signature contains the logic?|The final implementation signature.|
|Can implementation be narrower than overloads?|❌ No. It must accept all overload cases.|

### Common Interview Question

**Q: When does Function Overloading become powerful?**

**Answer:**

Use it when:

- One function supports **multiple valid input types**.
    
- Different inputs produce **different return types**.
    
- You're building **SDKs**, **utility libraries**, or **framework APIs**.
    
- You want excellent **autocomplete** and **compile-time validation**.
    
- You need a **clean API** instead of many similarly named functions.
    

### When NOT to Use It

- Only one parameter type exists.
    
- The logic is identical for all types.
    
- A simple union type (`string | number`) is sufficient.
    
- Overloads become too numerous and hard to maintain.
