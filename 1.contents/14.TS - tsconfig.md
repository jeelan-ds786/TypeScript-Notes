

# TSConfig Initialization

### Create a TypeScript Project

Install TypeScript:

```bash
npm install typescript --save-dev
```

Initialize TSConfig:

```bash
npx tsc --init
```

This creates:

```txt
tsconfig.json
```

### Compile Project

```bash
npx tsc
```

### Compile Single File

```bash
npx tsc app.ts
```

### Quick Revision

- `npx tsc --init` → creates tsconfig.json
    
- `npx tsc` → compiles project
    

# Sample tsconfig.json

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "strict": true,
    "rootDir": "./src",
    "outDir": "./dist"
  }
}
```

### Quick Revision

- `compilerOptions` contains TypeScript compiler settings.
    
- Most interview questions come from this section.
    

# Most Important TSConfig Options (Interview Focus)

|Option|Purpose|Common Value|
|---|---|---|
|`target`|JS version generated|`ES2022`, `ES2020`|
|`module`|Module system|`ESNext`, `CommonJS`|
|`strict`|Enables strict type checking|`true`|
|`rootDir`|Source folder|`src`|
|`outDir`|Output JS folder|`dist`|
|`lib`|Built-in JS APIs available|`DOM`, `ES2022`|
|`sourceMap`|Generates source maps|`true`|
|`removeComments`|Removes comments in JS output|`true`|
|`allowJs`|Allows JS files in project|`true/false`|
|`checkJs`|Type-check JS files|`true`|
|`noEmit`|Type check only, don't generate JS|`true`|
|`esModuleInterop`|Better compatibility with CommonJS packages|`true`|
|`skipLibCheck`|Skip type checking node_modules typings|`true`|
|`moduleResolution`|How imports are resolved|`Node`|
|`resolveJsonModule`|Import JSON files|`true`|
|`declaration`|Generate `.d.ts` files|`true`|

# target

Determines generated JavaScript version.

### Example

```json
{
  "target": "ES2022"
}
```

### Why?

TypeScript may convert modern JS syntax for older environments.

### Interview Takeaway

> `target` controls JavaScript output compatibility.

### Common Values

```txt
ES5
ES2015
ES2020
ES2022
ESNext
```

# module

Controls module format.

### Example

```json
{
  "module": "ESNext"
}
```

### Common Values

|Value|Usage|
|---|---|
|CommonJS|Node.js older projects|
|ESNext|React, Vite, Modern Apps|
|NodeNext|Modern Node.js|

### Quick Revision

- React/Vite → ESNext
    
- Old Node → CommonJS
    

# strict

Most important TSConfig setting.

### Example

```json
{
  "strict": true
}
```

Enables:

```txt
strictNullChecks
noImplicitAny
strictFunctionTypes
strictBindCallApply
strictPropertyInitialization
```

### Interview Takeaway

> Most companies expect strict mode enabled.

### Quick Revision

- Always keep `strict: true`.
    

# rootDir

Source code location.

### Example

```json
{
  "rootDir": "./src"
}
```

Project:

```txt
src/
 ├─ app.ts
 ├─ user.ts
```

### Quick Revision

- Input folder.
    

# outDir

Compiled JavaScript location.

### Example

```json
{
  "outDir": "./dist"
}
```

Output:

```txt
dist/
 ├─ app.js
 ├─ user.js
```

### Quick Revision

- Output folder.
    

# sourceMap

### Example

```json
{
  "sourceMap": true
}
```

Creates:

```txt
app.js.map
```

### Why?

Browser debugging maps JS back to TS.

### Interview Takeaway

> Helps debug TypeScript in browser DevTools.

### Quick Revision

- TS debugging feature.
    

# allowJs

### Example

```json
{
  "allowJs": true
}
```

Allows:

```txt
app.ts
helper.js
```

inside same project.

### Use Case

Migrating JS → TS gradually.

### Quick Revision

- Mixed JS + TS projects.
    

# checkJs

### Example

```json
{
  "checkJs": true
}
```

Type checks JavaScript files.

### Example

```js
function add(a, b) {
  return a + b;
}
```

TS can report errors even in JS files.

### Quick Revision

- Type checking without converting to TS.
    

# noEmit

### Example

```json
{
  "noEmit": true
}
```

Runs:

```txt
Type Checking Only
```

No JavaScript generated.

### Common Usage

React + Vite projects.

### Quick Revision

- Check types, don't build JS.
    

# esModuleInterop

Very common interview topic.

### Problem

```ts
import express from "express";
```

May fail with CommonJS packages.

### Solution

```json
{
  "esModuleInterop": true
}
```

### Quick Revision

- Better package compatibility.
    

# skipLibCheck

### Example

```json
{
  "skipLibCheck": true
}
```

Skips type checking:

```txt
node_modules
```

### Benefits

- Faster builds
    
- Fewer external library errors
    

### Quick Revision

- Almost always enabled.
    

# moduleResolution

### Example

```json
{
  "moduleResolution": "Node"
}
```

Controls how imports are located.

```ts
import user from "./user";
```

### Common Values

```txt
Node
NodeNext
Bundler
```

### Quick Revision

- Import resolution strategy.
    

# resolveJsonModule

### Example

```json
{
  "resolveJsonModule": true
}
```

Allows:

```ts
import config from "./config.json";
```

### Quick Revision

- Import JSON files directly.
    

# declaration

### Example

```json
{
  "declaration": true
}
```

Generates:

```txt
index.d.ts
```

Used by:

- Libraries
    
- SDKs
    
- NPM Packages
    

### Quick Revision

- Generates type definition files.
    

# Important Strict Mode Sub-Options

|Option|Purpose|
|---|---|
|`strictNullChecks`|Prevent null-related bugs|
|`noImplicitAny`|Prevent accidental any|
|`noUnusedLocals`|Detect unused variables|
|`noUnusedParameters`|Detect unused params|
|`noImplicitReturns`|Every path must return|
|`exactOptionalPropertyTypes`|Better optional property handling|
|`noFallthroughCasesInSwitch`|Prevent switch mistakes|

### Interview Takeaway

Most strictness-related questions come from these options.

# Common React/Vite TSConfig

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "strict": true,
    "jsx": "react-jsx",
    "moduleResolution": "Bundler",
    "allowJs": false,
    "skipLibCheck": true,
    "noEmit": true
  }
}
```

### Quick Revision

- This is close to what you'll see in modern frontend projects.
