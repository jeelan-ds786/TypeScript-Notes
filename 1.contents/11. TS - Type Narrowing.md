

# Type Narrowing

Type Narrowing is TypeScript's way of reducing a broad type into a more specific type.

### Example

```ts
let value: string | number;
```

At this point TypeScript only knows:

```txt
value = string OR number
```

Cannot do:

```ts
value.toUpperCase();
```

❌ Error

Because numbers don't have `toUpperCase()`.

---

### Narrowing with `typeof`

```ts
if (typeof value === "string") {
  value.toUpperCase();
}
```

Inside the block:

```txt
value = string
```

TypeScript narrowed the type.

### Quick Revision

- Narrowing = Convert broad type → specific type.
    

# Narrowing with `typeof`

### Example

```ts
function print(value: string | number) {
  if (typeof value === "string") {
    console.log(value.toUpperCase());
  }

  if (typeof value === "number") {
    console.log(value.toFixed(2));
  }
}
```

### Supported `typeof` Checks

```ts
typeof value === "string"
typeof value === "number"
typeof value === "boolean"
typeof value === "undefined"
typeof value === "function"
```

### Quick Revision

- `typeof` is the most common narrowing technique.
    

# Narrowing with `instanceof`

### Example

```ts
let date: Date | string;

if (date instanceof Date) {
  console.log(date.getFullYear());
}
```

Inside block:

```txt
date = Date
```

### Quick Revision

- `instanceof` works with classes.
    

# Narrowing with `Array.isArray`

### Example

```ts
let value: string[] | string;

if (Array.isArray(value)) {
  console.log(value.length);
}
```

TypeScript knows:

```txt
value = string[]
```

### Quick Revision

- Use `Array.isArray()` for arrays.
    

# Narrowing Unknown Types

### Example

```ts
let value: unknown;
```

Cannot do:

```ts
value.toUpperCase();
```

❌

Need narrowing:

```ts
if (typeof value === "string") {
  value.toUpperCase();
}
```

✅

### Interview Takeaway

> Unknown becomes useful only after narrowing.

### Quick Revision

- Unknown + Narrowing = Safe code.
    

# Non-Null Assertion Operator (`!`)

This is the `!` you are asking about.

### Example

```ts
let userName: string | null = "Fareed";
```

Normally:

```ts
userName.toUpperCase();
```

❌ Error

Because TypeScript thinks:

```txt
Could be null
```

---

### Using `!`

```ts
userName!.toUpperCase();
```

Meaning:

```txt
Trust me TypeScript,
this value is NOT null or undefined.
```

### Quick Revision

- `!` removes null/undefined checks.
    

# Real DOM Example

Very Common Interview Question

### Example

```ts
const btn =
  document.getElementById("submit");
```

Type:

```ts
HTMLElement | null
```

Because element may not exist.

---

### Error

```ts
btn.addEventListener(...);
```

❌

Could be null.

---

### Using `!`

```ts
const btn =
  document.getElementById("submit")!;

btn.addEventListener(...);
```

✅

Meaning:

```txt
I guarantee this element exists.
```

### Quick Revision

- Commonly used with DOM elements.
    

# Why Can `!` Be Dangerous?

### Example

```ts
let userName: string | null = null;

userName!.toUpperCase();
```

Compiles successfully.

Runtime:

```txt
Cannot read properties of null
```

💥 Crash

### Interview Takeaway

> `!` only silences TypeScript. It does not perform runtime checks.

### Quick Revision

- `!` removes compiler checks.
    
- Doesn't add safety.
    

# Better Alternative

Instead of:

```ts
userName!.toUpperCase();
```

Prefer:

```ts
if (userName) {
  userName.toUpperCase();
}
```

or

```ts
if (userName !== null) {
  userName.toUpperCase();
}
```

Now TypeScript narrows automatically.

### Quick Revision

- Narrowing > Non-null assertion.
    

# Optional Chaining vs `!`

### Non-Null Assertion

```ts
userName!.toUpperCase();
```

Assumes value exists.

---

### Optional Chaining

```ts
userName?.toUpperCase();
```

Meaning:

```txt
If userName exists,
call toUpperCase()
otherwise return undefined
```

Safer.

### Comparison

|Operator|Behavior|
|---|---|
|`!`|Trust me, not null|
|`?.`|Check for null safely|

### Quick Revision

- `!` = Assert
    
- `?.` = Safely check
    

# Common Interview Gotchas

|Question|Answer|
|---|---|
|What is Type Narrowing?|Converting broad type to specific type|
|Why is it needed?|Access type-specific methods safely|
|Common narrowing methods?|`typeof`, `instanceof`, `Array.isArray`|
|What does `!` mean?|Non-null assertion|
|Does `!` check runtime values?|No|
|Is `!` type-safe?|Not always|
|Better than `!`?|Type guards / narrowing|
|`?.` vs `!`?|Safe check vs assertion|

### Quick Revision

- Narrowing = TS learns more about a value.
    
- `typeof` = most common narrowing.
    
- `!` = "Trust me, it's not null."
    
- `?.` = safer alternative.
    
- Prefer actual checks over `!` whenever possible.
