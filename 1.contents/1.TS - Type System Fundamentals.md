

# Why TypeScript? (TypeScript vs JavaScript)

- JavaScript is **dynamically typed** → type checking happens at runtime.
    
- TypeScript is a **superset of JavaScript** → adds static typing on top of JS.
    
- TypeScript catches errors during development before code reaches production.
    
- Better IDE support: autocomplete, refactoring, navigation, IntelliSense.
    
- Improves maintainability in large frontend applications.
    

### Quick Revision

- **JavaScript = Runtime Safety**
    
- **TypeScript = Compile-Time Safety**
    

# Why Do We Need TypeScript?

### Problem in JavaScript

```js
function calculateDiscount(price, discount) {
  return price - discount;
}

calculateDiscount("1000", 200);
```

- JavaScript allows mixed types.
    
- Result may be unexpected due to implicit type coercion.
    
- Bugs are discovered only while running the application.
    

### TypeScript Solution

```ts
function calculateDiscount(
  price: number,
  discount: number
): number {
  return price - discount;
}

calculateDiscount("1000", 200);
```

❌ Compile Error

```txt
Argument of type 'string'
is not assignable to parameter of type 'number'
```

### Benefits

- Prevents accidental string/number mixing.
    
- Detects bugs before deployment.
    
- Makes APIs self-documenting.
    

### Quick Revision

- TypeScript prevents "wrong type" bugs before execution.
    

# Calculator Example (Real Interview Scenario)

### JavaScript Version

```js
function totalPrice(price, tax) {
  return price + tax;
}

totalPrice("100", 10);
```

Output:

```js
"10010"
```

### Why?

- `+` operator performs string concatenation.
    
- JavaScript infers first operand as string.
    

### TypeScript Version

```ts
function totalPrice(
  price: number,
  tax: number
): number {
  return price + tax;
}

totalPrice("100", 10);
```

Compiler Error:

```txt
Type 'string' is not assignable to type 'number'
```

### Interview Takeaway

- TypeScript removes accidental type coercion issues.
    
- Reduces production bugs significantly.
    

### Quick Revision

- JS → "100" + 10 = "10010"
    
- TS → Compile-time error
    

# How TypeScript Converts into JavaScript

### TypeScript Compilation Flow

```text
Developer
    |
    v
TypeScript (.ts)
    |
    v
Type Checking
    |
    v
Compiler (tsc)
    |
    v
Remove Type Annotations
    |
    v
JavaScript (.js)
    |
    v
Browser / Node.js
```

### Example

TypeScript:

```ts
let age: number = 25;

function greet(name: string): string {
  return `Hello ${name}`;
}
```

### Compilation Step

Type information is removed.

Generated JavaScript:

```js
let age = 25;

function greet(name) {
  return `Hello ${name}`;
}
```

### Important Interview Point

- Browsers do NOT understand TypeScript.
    
- Browser only executes JavaScript.
    
- TypeScript compiler removes all type-related syntax.
    

### Flow Explanation

```text
.ts file
   |
   | Static Type Checking
   |
   v
TypeScript Compiler (tsc)
   |
   | Removes Types
   |
   v
JavaScript File (.js)
   |
   v
Browser Executes
```

### Quick Revision

- TypeScript exists only during development.
    
- JavaScript exists in production.
    

# TypeScript Compilation Process (Deep Dive)

### Step 1: Write TypeScript

```ts
let username: string = "Fareed";
```

### Step 2: Parsing

- Compiler reads source code.
    
- Creates AST (Abstract Syntax Tree).
    

### Step 3: Type Checking

- Validates assigned values.
    
- Detects type mismatches.
    

### Step 4: Transpilation

- Removes TypeScript-specific syntax.
    
- Converts modern JS features if configured.
    

### Step 5: JavaScript Output

```js
let username = "Fareed";
```

### Step 6: Runtime Execution

- Browser runs JavaScript.
    
- TypeScript no longer exists.
    

### Interview Trap

|Question|Answer|
|---|---|
|Does TypeScript run in browser?|No|
|Does TS improve runtime performance?|No|
|Is TS compiled or interpreted?|Transpiled to JS|
|Does TS exist in production bundle?|Only generated JS exists|

### Quick Revision

- Parse → Type Check → Transpile → Run

# TypeScript Advantages for Frontend Interviews

- Better API contract validation.

### Common Interview Answer

- Large app/team → TS preferred.
