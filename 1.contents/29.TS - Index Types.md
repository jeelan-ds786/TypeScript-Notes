

# Index Signatures (Index Types)

- **Index signatures** define the type of **dynamic object keys**.
    
- Use them when you **don't know property names in advance**.
    
- Common in configurations, API responses, dictionaries, caches, and lookup tables.
    
- Every property accessed through the index must match the declared value type.
    

```ts
interface UserScores {
  [key: string]: number;
}

const scores: UserScores = {
  john: 95,
  alice: 88,
};
```

### When do Index Signatures play a major role?

- Dynamic API response objects
    
- Translation (i18n) dictionaries
    
- Feature flags
    
- Cache objects
    
- Lookup tables
    

**Quick Revision:**

> Unknown keys → Use an index signature.

### Can the key be `number`?

Given:

```ts
interface Obj {
  [prop: string]: number | boolean;
}
```

Is this allowed?

```ts
obj[123] = true;
```

✅ **Yes.**

Reason:

In JavaScript, numeric object keys are automatically converted to strings.

```ts
const obj = {};

obj[1] = "Hello";

console.log(obj);
// { "1": "Hello" }
```

If you specifically want numeric indexing (commonly for arrays), you can write:

```ts
interface NumMap {
  [index: number]: string;
}
```

**Interview Gotcha**

|Question|Answer|
|---|---|
|Does `[key: string]` allow numeric keys?|✅ Yes. Numbers are converted to strings in JavaScript.|
|Does `[key: number]` allow arbitrary strings?|❌ No. It only describes numeric indexing.|

### `as const` with Arrays

Without `as const`:

```ts
const roles = ["admin", "teacher"];
```

Type becomes:

```ts
string[]
```

So:

```ts
const firstRole = roles[0];
// string
```

---

With `as const`:

```ts
const roles = ["admin", "teacher"] as const;
```

Type becomes:

```ts
readonly ["admin", "teacher"]
```

Now:

```ts
const firstRole = roles[0];
// "admin"
```

Notice:

- `roles[0]` is the literal type `"admin"`, not `string`.
    
- The array is **readonly**, so you cannot modify it.
    

```ts
roles.push("student"); // ❌ Error
roles[0] = "teacher";  // ❌ Error
```

**Quick Revision:**

> `as const` preserves literal values and makes arrays/objects readonly.

### Your Example

Instead of:

```ts
let role = ['admin' | 'teacher'] as const
```

✅ Correct syntax:

```ts
const roles = ["admin", "teacher"] as const;

const firstRole = roles[0];
// "admin"
```

If you want a variable that can hold either value:

```ts
type Role = typeof roles[number];
// "admin" | "teacher"

let role: Role = "admin";
```

This `typeof array[number]` pattern is a very common interview question.

### `Record<K, T>`

`Record` is a utility type that creates an object type with known key and value types.

Syntax:

```ts
Record<Keys, ValueType>
```

Example:

```ts
type Scores = Record<string, number>;

const scores: Scores = {
  alice: 90,
  bob: 85,
};
```

Equivalent to:

```ts
{
  [key: string]: number;
}
```

---

Your example:

```ts
Record<string, number | boolean>
```

means:

```ts
const obj: Record<string, number | boolean> = {
  age: 25,
  active: true,
  score: 98,
};
```

Equivalent to:

```ts
{
  [key: string]: number | boolean;
}
```

### Index Signature vs `Record`

|Question|Index Signature|`Record`|
|---|---|---|
|Syntax|`{ [key: string]: T }`|`Record<K, T>`|
|Readability|Good|Better|
|Dynamic keys|✅ Yes|✅ Yes|
|Preferred in modern TS|Good|✅ Often preferred|
|Common interview use|Dictionaries, caches|Config maps, lookup objects|

**Quick Revision:**

> `Record<K, T>` is essentially a cleaner way to write an index signature.

### Interview Gotchas

|Question|Answer|
|---|---|
|Are object keys really numbers?|❌ No. JavaScript converts object keys to strings (except `Symbol` keys).|
|What does `as const` do?|Preserves literal types and makes arrays/objects `readonly`.|
|What is `typeof arr[number]`?|Creates a union of all array element types.|
|Is `Record<string, T>` the same as `{ [key: string]: T }`?|✅ Yes, functionally equivalent.|
|When should you use an index signature?|When property names are not known ahead of time.|

| Topic                 | Quick Recall                                                       |
| --------------------- | ------------------------------------------------------------------ |
| Index Signature       | Dynamic object keys with a fixed value type                        |
| Number vs String Keys | Number keys become strings in JavaScript objects                   |
| `as const`            | Preserves literal values and makes data `readonly`                 |
| `typeof arr[number]`  | Produces a union of all element literal types                      |
| `Record<K, T>`        | Cleaner syntax for defining object maps with typed keys and values |
