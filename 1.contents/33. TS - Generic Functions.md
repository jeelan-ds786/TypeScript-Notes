# How is a Generic Function Built?

Think of a generic function as a **normal function with a type placeholder (`T`)**.

Instead of hardcoding `string` or `number`, we write:

```ts
<T>
```

This means:

> "I don't know the type yet. Tell me when you call the function."

---

# Step 1 — Normal Function

This only works for strings.

```ts
function identity(value: string): string {
    return value;
}
```

Usage:

```ts
identity("Hello");   // ✅
identity(10);        // ❌ Error
```

---

# Step 2 — Replace the Type with a Placeholder

```ts
function identity<T>(value: T): T {
    return value;
}
```

Notice what changed:

```ts
function identity<T>(value: T): T
                  ↑          ↑    ↑
          Generic Type   Parameter Return Type
```

Now it works for **any type**.

---

# Step 3 — Type is Decided When Calling

```ts
identity<string>("Hello");
```

TypeScript internally treats it like:

```ts
function identity(value: string): string
```

---

Another call:

```ts
identity<number>(100);
```

Internally becomes:

```ts
function identity(value: number): number
```

---

Another:

```ts
identity<boolean>(true);
```

Internally:

```ts
function identity(value: boolean): boolean
```

The function body **does not change**.

Only **`T` gets replaced**.

---

# Type Inference (Most Common)

Usually, you don't specify `T`.

```ts
identity("Hello");
```

TypeScript automatically infers:

```ts
T = string
```

Similarly:

```ts
identity(10);
```

↓

```ts
T = number
```

This is called **Type Inference**.

---

# How Does TypeScript "Build" It?

Your code:

```ts
function identity<T>(value: T): T {
    return value;
}
```

Think of it as a **template**.

When called like:

```ts
identity("Hello")
```

TypeScript conceptually creates:

```ts
identity(value: string): string
```

When called like:

```ts
identity(50)
```

It conceptually creates:

```ts
identity(value: number): number
```

> **Important:** TypeScript does **not** generate multiple JavaScript functions. This substitution happens only at **compile time** for type checking.

---

# Multiple Generic Parameters

You can have more than one placeholder.

```ts
function pair<K, V>(key: K, value: V) {
    return {
        key,
        value
    };
}
```

Usage:

```ts
pair("id", 100);
```

TypeScript infers:

```ts
K = string
V = number
```

Result type:

```ts
{
    key: string;
    value: number;
}
```

---

# Generic with Arrays

```ts
function first<T>(items: T[]): T {
    return items[0];
}
```

Call:

```ts
first(["A", "B"]);
```

↓

```ts
T = string
```

Call:

```ts
first([10, 20]);
```

↓

```ts
T = number
```

---

# Generic Constraints

Sometimes you want **any type**, but with a condition.

Example:

```ts
function printLength<T extends { length: number }>(item: T) {
    console.log(item.length);
}
```

Works:

```ts
printLength("Hello");
printLength([1, 2, 3]);
```

Error:

```ts
printLength(100);
```

Because `number` doesn't have a `length` property.

---

# How `Array<T>` is Implemented

This is roughly how TypeScript defines `Array`:

```ts
interface Array<T> {
    length: number;

    push(item: T): number;

    pop(): T | undefined;

    map<U>(callback: (item: T) => U): U[];
}
```

If you write:

```ts
const names: Array<string> = [];
```

TypeScript substitutes:

```ts
push(item: string)
pop(): string | undefined
```

If you write:

```ts
const nums: Array<number> = [];
```

It becomes:

```ts
push(item: number)
pop(): number | undefined
```

One implementation, many types.

# Interview Mental Model

Imagine `T` is a **blank box**.

```text
function getValue<T>(value: T): T
                   ▲
              Empty box
```

Call:

```ts
getValue("Hello")
```

↓

```text
T = string
```

Call:

```ts
getValue(100)
```

↓

```text
T = number
```

The **caller fills in the blank**.

# Interview Gotchas

|Question|Answer|
|---|---|
|Does TypeScript create multiple JavaScript functions?|❌ No. Generics exist only during type checking.|
|What is `T`?|A type parameter (placeholder for a type).|
|Can a generic have multiple type parameters?|✅ Yes (`<T, K, V>`).|
|Can TypeScript infer generic types?|✅ Yes, in most cases you don't need to write `<string>` or `<number>`.|
|Can generics be constrained?|✅ Yes, using `extends` (e.g., `T extends { length: number }`).|

---

## Quick Interview Answer

**Q: How do you build a generic function?**

> "You declare a type parameter, usually `<T>`, after the function name. Then you use `T` for the parameter and/or return type. When the function is called, TypeScript either infers the actual type or you provide it explicitly. This lets one implementation work safely with many different types without duplicating code."
