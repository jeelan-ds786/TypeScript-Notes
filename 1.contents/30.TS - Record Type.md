# `Record<K, T>`

`Record<K, T>` is a built-in TypeScript utility type used to create an object where:

- **`K`** = Type of the keys
    
- **`T`** = Type of the values
    

```ts
Record<Keys, ValueType>
```

**Quick Revision:**

> `Record` = "Every key of type `K` must have a value of type `T`."

### Example 1: `Record<string, number>`

```ts
type Scores = Record<string, number>;

const scores: Scores = {
  math: 95,
  science: 88,
  english: 91,
};
```

Equivalent to:

```ts
type Scores = {
  [key: string]: number;
};
```

Any string key is allowed, but every value must be a `number`.

```ts
scores.history = 80;     // ✅
scores.physics = "90";   // ❌ Error
```

### Example 2: `Record<string, number | boolean>`

This matches what you asked about.

```ts
type Data = Record<string, number | boolean>;

const obj: Data = {
  age: 24,
  isAdmin: true,
  score: 95,
};
```

All values must be either:

- `number`
    
- `boolean`
    

These are **not** allowed:

```ts
const obj: Data = {
  age: 24,
  name: "Fareed",   // ❌ string not allowed
};
```

### Example 3: Fixed Keys

`Record` becomes even more powerful when keys are known.

```ts
type User = Record<"name" | "age", string | number>;

const user: User = {
  name: "Fareed",
  age: 24,
};
```

Missing a required key:

```ts
const user: User = {
  name: "Fareed",
};
// ❌ Property 'age' is missing
```

Extra keys:

```ts
const user: User = {
  name: "Fareed",
  age: 24,
  city: "Chennai",
};
// ❌ Error
```

When `K` is a union of literal keys, **all keys are required**.

### Real-Time Example: Role Permissions

```ts
type Permission = Record<
  "admin" | "teacher" | "student",
  boolean
>;

const permissions: Permission = {
  admin: true,
  teacher: true,
  student: false,
};
```

Very common in frontend applications for feature flags and permissions.

### Real-Time Example: Product Prices

```ts
type Prices = Record<string, number>;

const prices: Prices = {
  apple: 120,
  mango: 80,
  orange: 100,
};
```

Useful for:

- Price lists
    
- Translation dictionaries
    
- API lookup maps
    
- Configuration objects
    

### How Does It Work Internally?

TypeScript defines `Record` roughly like this:

```ts
type Record<K extends keyof any, T> = {
  [P in K]: T;
};
```

Breaking it down:

```ts
Record<"a" | "b", number>
```

becomes

```ts
{
  a: number;
  b: number;
}
```

This uses a **mapped type**, where TypeScript loops over each key in `K`.

### `Record` vs Index Signature

```ts
Record<string, number>
```

is equivalent to

```ts
{
  [key: string]: number;
}
```

The main difference is readability and intent.

### Interview Gotchas

|Question|Answer|
|---|---|
|What does `Record<K, T>` do?|Creates an object with keys of type `K` and values of type `T`.|
|Is `Record<string, number>` the same as `{ [key: string]: number }`?|✅ Yes.|
|What happens with `Record<"a" \| "b", number>`?|Both `a` and `b` are required.|
|Can values have different types?|Only if `T` is a union (e.g., `number \| boolean`).|
|When is `Record` preferred?|For lookup tables, configs, permissions, and dictionaries.|

| Topic                               | Quick Recall                                        |
| ----------------------------------- | --------------------------------------------------- |
| `Record<K, T>`                      | Creates an object type with keys `K` and values `T` |
| `Record<string, number>`            | Any string key → number value                       |
| `Record<string, number \| boolean>` | Any string key → number or boolean value            |
| `Record<"a" \| "b", T>`             | Fixed required keys `a` and `b`                     |
| Internal Working                    | Uses a mapped type: `{ [P in K]: T }`               |
