

# Inheritance in TypeScript

- Inheritance allows one class to acquire properties and methods of another class
    
- Promotes code reuse
    
- Implemented using the `extends` keyword
    
- Child class inherits from parent class
    
- Quick revision: **Inheritance = reuse existing code instead of rewriting it**
    

# Basic Inheritance

```ts
class Animal {
  eat() {
    console.log("Eating");
  }
}

class Dog extends Animal {
  bark() {
    console.log("Barking");
  }
}

const dog = new Dog();

dog.eat();
dog.bark();
```

### Output

```txt
Eating
Barking
```

### What Happened?

```txt
Animal (Parent)
    ↑
    |
Dog (Child)
```

- `Dog` gets its own methods
    
- `Dog` also gets all public/protected members from `Animal`
    

# Why Do We Need Inheritance?

Without inheritance:

```ts
class Dog {
  eat() {}
  sleep() {}
}

class Cat {
  eat() {}
  sleep() {}
}
```

Duplicate code ❌

With inheritance:

```ts
class Animal {
  eat() {}
  sleep() {}
}

class Dog extends Animal {}

class Cat extends Animal {}
```

Reuse code ✅

### Interview Recall

- Reduces duplication
    
- Improves maintainability
    

# Constructor Inheritance & `super()`

Parent:

```ts
class Animal {
  constructor(public name: string) {}
}
```

Child:

```ts
class Dog extends Animal {
  constructor(name: string) {
    super(name);
  }
}
```

### Why `super()`?

- Calls parent constructor
    
- Initializes parent properties
    
- Must be called before using `this`
    

### Interview Trap

```ts
class Dog extends Animal {
  constructor(name: string) {
    this.name = name; // ❌ Error
  }
}
```

Must call:

```ts
super(name);
```

first.

# Access Modifiers in Inheritance

```ts
class Animal {
  public type = "Animal";
  protected age = 5;
  private secret = "Hidden";
}
```

Child:

```ts
class Dog extends Animal {
  show() {
    console.log(this.type); // ✅
    console.log(this.age);  // ✅
    // console.log(this.secret); ❌
  }
}
```

### Access Rules

|Modifier|Parent|Child|Outside|
|---|---|---|---|
|public|✅|✅|✅|
|protected|✅|✅|❌|
|private|✅|❌|❌|

### Interview Recall

- `protected` exists mainly for inheritance scenarios
    

# Method Overriding

Parent:

```ts
class Animal {
  speak() {
    console.log("Animal sound");
  }
}
```

Child:

```ts
class Dog extends Animal {
  speak() {
    console.log("Bark");
  }
}
```

Usage:

```ts
const dog = new Dog();

dog.speak();
```

Output:

```txt
Bark
```

### What Happened?

- Child replaced parent implementation
    
- This is called **method overriding**
    

### Interview One-Liner

> Method overriding occurs when a child class provides its own implementation of a parent method.

# Calling Parent Method Using `super`

```ts
class Animal {
  speak() {
    console.log("Animal sound");
  }
}

class Dog extends Animal {
  speak() {
    super.speak();
    console.log("Bark");
  }
}
```

Output:

```txt
Animal sound
Bark
```

### Quick Recall

- `super.method()` → call parent implementation
    

# Multi-Level Inheritance

```ts
class Animal {
  eat() {}
}

class Dog extends Animal {
  bark() {}
}

class Puppy extends Dog {
  play() {}
}
```

Hierarchy:

```txt
Animal
   ↑
 Dog
   ↑
Puppy
```

`Puppy` gets:

- eat()
    
- bark()
    
- play()
    

### Interview Recall

- TypeScript supports multi-level inheritance
    

# Single Inheritance Only

✅ Allowed

```ts
class Dog extends Animal {}
```

❌ Not Allowed

```ts
class Dog extends Animal, Pet {}
```

### Why?

JavaScript classes support only single inheritance.

For multiple behaviors:

```ts
interface Flyable {}
interface Swimmable {}

class Bird implements Flyable, Swimmable {}
```

### Interview Trap

|Question|Answer|
|---|---|
|Multiple inheritance in TS classes?|No|
|Multiple interfaces?|Yes|

# Real Industry Example

```ts
class BaseComponent {
  loading = false;

  showLoader() {
    this.loading = true;
  }
}

class UserComponent extends BaseComponent {
  fetchUsers() {
    this.showLoader();
  }
}
```

Why?

- Shared logic lives in parent class
    
- Child classes reuse it
    

Common in:

- Angular
    
- Backend services
    
- UI component libraries
    

# Common Interview Questions

|Question|Answer|
|---|---|
|Which keyword is used for inheritance?|`extends`|
|Why use inheritance?|Code reuse|
|What does `super()` do?|Calls parent constructor|
|What does `super.method()` do?|Calls parent method|
|Can child access private members?|No|
|Can child access protected members?|Yes|
|Does TS support multiple inheritance?|No|
|Can TS implement multiple interfaces?|Yes|

# Common Interview Traps

|Trap Question|Correct Answer|
|---|---|
|Must `super()` be called first?|Yes|
|Can private members be inherited?|No|
|Does child automatically get parent constructor?|No, `super()` initializes it|
|Is inheritance same as interface implementation?|No|
|Can one class extend two classes?|No|

# Quick Recall

- `extends` → inheritance
    
- Parent = base class
    
- Child = derived class
    
- `super()` → parent constructor
    
- `super.method()` → parent method
    
- Override → replace parent method
    
- `protected` works with inheritance
    
- Multiple class inheritance ❌
    
- Multiple interfaces ✅
