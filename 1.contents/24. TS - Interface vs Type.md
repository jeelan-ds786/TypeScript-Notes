

# Interface vs Type — When Should You Use Which?

## Use `interface` When

- Defining object shapes
    
- Defining API contracts
    
- Creating class contracts
    
- Expecting future extension
    
- Working in React/Angular enterprise projects
    

```ts
interface User {
  id: number;
  name: string;
}
```

### Why?

- Supports `extends`
    
- Supports declaration merging
    
- More readable for object models
    

### Industry Rule

> If you're describing an object or class contract, prefer `interface`.

# Use `type` When

- Creating unions
    
- Creating intersections
    
- Creating primitive aliases
    
- Using mapped/conditional types
    
- Advanced TypeScript features
    

### Union

```ts
type Status =
  | "loading"
  | "success"
  | "error";
```

### Primitive Alias

```ts
type UserId = string;
```

### Intersection

```ts
type Employee =
  Person &
  Address;
```

### Interview Recall

> If you need `|`, `&`, mapped types, conditional types → use `type`.

# Real Project Rule

### Object Models

```ts
interface User {
  id: number;
  name: string;
}
```

### Enums / States

```ts
type Theme =
  | "light"
  | "dark";
```

### API Responses

```ts
interface ApiResponse {
  data: User[];
}
```

### Advanced Utility Types

```ts
type PartialUser =
  Partial<User>;
```

### Interview One-Liner

> Interface for object contracts. Type for type composition and advanced typing.

# `implements` Keyword

`implements` is used by a **class** to follow an interface contract.

Interface:

```ts
interface Animal {
  speak(): void;
}
```

Class:

```ts
class Dog implements Animal {
  speak() {
    console.log("Bark");
  }
}
```

TypeScript checks:

```txt
Does Dog contain speak() ?
```

If yes ✅

If no ❌ Compile Error

# Why Do We Need `implements`?

Without it:

```ts
class Dog {
  bark() {}
}
```

No guarantee about structure.

With it:

```ts
interface Animal {
  speak(): void;
}

class Dog implements Animal {
  speak() {}
}
```

Now every developer must follow the contract.

### Interview Recall

- `implements` = contract enforcement
    
- Compile-time check only
    

# What Happens If Method Is Missing?

```ts
interface Animal {
  speak(): void;
}

class Dog implements Animal {
}
```

❌ Error

```txt
Class 'Dog' incorrectly implements interface 'Animal'
```

Because `speak()` is missing.

# Multiple Interfaces

A class can implement multiple interfaces.

```ts
interface Flyable {
  fly(): void;
}

interface Swimmable {
  swim(): void;
}

class Duck
  implements Flyable, Swimmable {

  fly() {}

  swim() {}
}
```

### Interview Recall

- Multiple inheritance ❌
    
- Multiple interfaces ✅
    

# `extends` vs `implements`

This is a favorite interview question.

### extends

```ts
class Animal {
  eat() {}
}

class Dog extends Animal {}
```

Meaning:

```txt
Dog IS-A Animal
```

Dog inherits code.

---

### implements

```ts
interface Animal {
  speak(): void;
}

class Dog implements Animal {
  speak() {}
}
```

Meaning:

```txt
Dog FOLLOWS Animal contract
```

No code inheritance.

### Comparison

|Feature|extends|implements|
|---|---|---|
|Used With|Class / Interface|Class|
|Inherits Implementation|✅|❌|
|Enforces Contract|❌|✅|
|Reuses Code|✅|❌|
|Multiple Allowed|Interfaces only|Yes|

### Interview One-Liner

> `extends` gives implementation inheritance. `implements` gives contract enforcement.

# Common Interview Questions

|Question|Answer|
|---|---|
|When should you use interface?|Object contracts|
|When should you use type?|Unions, intersections, advanced types|
|Can interface create unions?|No|
|Can type create unions?|Yes|
|What does implements do?|Ensures class follows interface contract|
|Does implements generate JavaScript?|No|
|Can class implement multiple interfaces?|Yes|
|Difference between extends and implements?|Inheritance vs contract|

# Interview Traps

|Trap Question|Correct Answer|
|---|---|
|Does implements inherit code?|No|
|Does interface exist at runtime?|No|
|Can type aliases merge automatically?|No|
|Can interfaces merge automatically?|Yes|
|Can a class implement a type?|Yes, if the type resolves to an object shape|
|Does implements generate JavaScript code?|No|

### Interesting Interview Question

```ts
type Person = {
  name: string;
};

class User implements Person {
  name = "Fareed";
}
```

✅ Valid

Because `Person` describes an object shape.

`implements` can work with interfaces and object-shaped types.

# Quick Recall

- Interface → Object contracts
    
- Type → Unions, intersections, advanced typing
    
- implements → Class follows contract
    
- extends → Inherits implementation
    
- Multiple interfaces ✅
    
- Multiple class inheritance ❌
    
- implements is compile-time only
    

|Topic|Quick Recall|
|---|---|
|Interface|Object contract|
|Type|Advanced type composition|
|Interface Use Case|APIs, DTOs, models|
|Type Use Case|Union, Intersection, Utility types|
|implements|Follow contract|
|extends|Inherit code|
|Multiple Interfaces|Supported|
|Multiple Class Inheritance|Not supported|
|Runtime Impact|None (compile-time only)|
